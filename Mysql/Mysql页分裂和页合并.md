页分裂和页合并是 **InnoDB存储引擎维护B+树索引结构时的重要机制**。

先理解一个概念：

## 1. 什么是页（Page）？

InnoDB存储数据的基本单位不是一行，而是：

> **页（Page）**

默认大小：

```
16KB
```

一页里面存放：

```
一页(Page)
|
|-- 多条数据记录
|
|-- 页目录
|
|-- 指针信息
```

B+树的节点实际上就是一个个页：

```
        根页
         |
   ----------------
   |              |
 叶子页1        叶子页2
   |
 数据记录
```

---

# 一、页分裂（Page Split）

## 1. 什么情况下发生？

当：

> 插入数据时，目标页已经满了。

例如：

一个页只能存：

```
5条数据
```

现在：

```
页1：

id
1
2
3
4
5
```

已经满了。

此时插入：

```
id=6
```

怎么办？

不能继续放。

于是发生：

> 页分裂

---

# 2. 页分裂过程

原来：

```
Page1

1
2
3
4
5
```

插入：

```
6
```

超过容量。

拆分：

```
        父节点

          |
    ------------
    |          |

 Page1       Page2

1 2 3       4 5 6
```

过程：

1. 创建新页
2. 把原页部分数据移动到新页
3. 修改父节点指针
4. 插入新数据

---

# 3. 为什么页分裂影响性能？

因为需要：

### ① 数据移动

原来的：

```
1 2 3 4 5
```

需要拆成：

```
1 2 3

4 5
```

涉及数据搬迁。

---

### ② 修改B+树结构

需要更新：

- 父节点
- 页指针

---

### ③ 增加IO

可能需要：

```
读页
 ↓
创建新页
 ↓
写页
```

所以：

> 页分裂会降低写入性能。

---

# 二、为什么自增主键减少页分裂？

这是面试重点。

## 情况1：自增ID

插入：

```
1
2
3
4
5
6
```

数据一直追加：

```
Page1

1
2
3
4
5

↓

Page2

6
7
8
```

特点：

```
顺序写入
```

页分裂少。

---

## 情况2：UUID主键

例如：

```
8f23
1a55
9b77
3c22
```

随机插入。

B+树：

```
        5

  1          9
```

可能：

```
中间插入
```

导致：

```
页满
 ↓
分裂
```

频繁发生。

所以：

> InnoDB推荐使用自增主键。

---

# 三、页合并（Page Merge）

## 1. 什么情况下发生？

当：

> 页中删除的记录达到MERGE_THRESHOLD(默认为页的50%)，页中数据太少



例如：

页容量：

```
5条
```

当前：

```
Page1

1
2
3
```

删除：

```
1
2
```

剩：

```
3
```

空间利用率太低。

于是：

> 页合并

---

# 2. 页合并过程

原：

```
Page1

3


Page2

4
5
6
```

合并：

```
Page1

3
4
5
6
```

然后：

删除空页。

同时：

更新父节点指针。

---

# 四、页合并影响性能

页合并需要：

- 移动数据
- 修改索引结构

因此：

大量删除操作可能导致：

```
页合并频繁
 ↓
性能下降
```

---

# 五、页分裂和页合并对比

||页分裂|页合并|
|---|---|---|
|发生场景|插入数据|删除数据|
|原因|页空间不足|页利用率过低|
|动作|拆成两个页|多个页合成一个|
|影响|降低写入性能|降低删除性能|
|维护对象|B+树结构|B+树结构|

---

# 六、和主键设计的关系

## 推荐：

```
id BIGINT AUTO_INCREMENT PRIMARY KEY
```

原因：

数据：

```
1
2
3
4
5
```

插入位置：

```
最右侧叶子节点
```

减少：

- 页分裂
- 数据移动

---

## 不推荐：

```
id UUID PRIMARY KEY
```

原因：

随机：

```
52af
13bc
9dea
```

导致：

```
随机插入
 ↓
页分裂
 ↓
性能下降
```

# 七、面试回答模板

### Q：什么是页分裂？

回答：

> InnoDB使用B+树组织索引，当向一个已经满的页中插入数据时，由于空间不足，会创建新的页，并将原页中的部分数据移动到新页，同时调整父节点指针，这个过程叫页分裂。

---

### Q：为什么推荐使用自增主键？

回答：

> 因为自增主键的数据按照递增顺序插入，新的数据通常追加到B+树最右侧叶子节点，可以减少页分裂，提高插入性能。而随机主键会导致大量中间插入，引起频繁页分裂。
