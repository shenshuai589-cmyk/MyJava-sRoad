
## 1. 什么是存储过程？

**存储过程是一组预先编译好的 SQL 语句集合，存储在数据库服务器中，通过调用名称来执行。**

简单理解：

> 把一堆经常使用的 SQL 语句封装起来，像调用 Java 方法一样调用。

例如 Java 方法：

```
public void addUser(String name){
    // 插入用户
}
```

MySQL 存储过程：

```
CALL add_user('张三');
```

数据库内部执行提前写好的 SQL。


# 2. 为什么使用存储过程？

## （1）减少网络传输

普通 SQL：

```
应用服务器
    |
    | 发送SQL1
    ↓
数据库执行

    |
    | 发送SQL2
    ↓
数据库执行

    |
    | 发送SQL3
    ↓
数据库执行
```

多次网络交互。

存储过程：

```
应用服务器

CALL procedure()

        ↓

数据库一次执行全部SQL
```

减少通信次数。

---

## （2）提高执行效率

存储过程创建后：

- SQL 会被解析
- 执行计划可能被缓存

再次调用：

```
CALL xxx()
```

不需要重新解析。

---

## （3）提高安全性

例如：

不给用户直接操作表：

```
SELECT
INSERT
UPDATE
```

权限。

只允许：

```
CALL create_order()
```

通过存储过程控制。

## 3.存储过程基本语法

### 3.1 创建

```sql
create procedure 存储过程名()
begin
	sql语句
	
end;
```

例如：

创建查询所有用户：

```
DELIMITER //

CREATE PROCEDURE find_all_user()
BEGIN

    SELECT * FROM user;

END //

DELIMITER ;
```

#### 3.1.1 DELIMITER 

delimiter是用来改变语句分隔符（定界符）的命令

### 为什么需要它？

默认情况下，MySQL 使用分号（`;`）作为一条 SQL 语句的结束标志。

但是，当你需要编写存储过程（Stored Procedure）、存储函数（Function）或触发器（Trigger）时，内部代码段（如 `BEGIN ... END;`）包含多个分号。如果不修改分隔符，MySQL 读到内部的第一个分号就会以为整条命令结束了，从而导致语法报错。

注意：delimiter是会话级别的，一旦设置成了别的符号作为结束语句，那么当前会话中所有语句的结束语句都要换成被替换的结束语句。

## 3.2 调用

```sql
call 存储过程名();
```

例如：

```
DELIMITER //

CREATE PROCEDURE find_user(IN uid INT)
BEGIN

SELECT *
FROM user
WHERE id = uid;

END //

DELIMITER ;
```

调用：

```
CALL find_user(1);
```

# 4. 存储过程参数

存储过程支持三种参数：

|类型|作用|
|---|---|
|IN|输入参数|
|OUT|输出参数|
|INOUT|输入输出参数|

---

# 4.1 IN 输入参数

调用时传入。

例如：

根据 id 查询用户。

```
DELIMITER //

CREATE PROCEDURE find_user(IN uid INT)
BEGIN

SELECT *
FROM user
WHERE id = uid;

END //

DELIMITER ;
```

调用：

```
CALL find_user(1);
```

执行：

```
SELECT *
FROM user
WHERE id=1;
```

---

# 4.2 OUT 输出参数

存储过程中返回结果。

例如：

查询用户数量。

创建：

```
DELIMITER //

CREATE PROCEDURE count_user(OUT total INT)
BEGIN

SELECT COUNT(*)
INTO total
FROM user;

END //

DELIMITER ;
```

调用：

先定义变量：

```
SET @num = 0;
```

调用：

```
CALL count_user(@num);
```

查看：

```
SELECT @num;
```

结果：

```
@num
100
```

---

# 4.3 INOUT 输入输出

既可以传入，也可以修改。

例如：

数字加10。

```
DELIMITER //

CREATE PROCEDURE add_num(INOUT num INT)
BEGIN

SET num = num + 10;

END //

DELIMITER ;
```

调用：

```
SET @n = 5;

CALL add_num(@n);

SELECT @n;
```

结果：

```
15
```

DECLARE 变量名 类型;

# 7. 流程控制

存储过程支持：

- IF
- CASE
- WHILE
- LOOP
- REPEAT

---

### 1. 条件判断：`IF` 与 `CASE`

#### `IF` 语句（适合简单或区间条件）

标准的条件判断分支。

SQL

```sql
IF score >= 90 THEN
    SET grade = 'A';
ELSEIF score >= 60 THEN
    SET grade = 'B';
ELSE
    SET grade = 'C';
END IF;
```

#### `CASE` 语句（适合多分支相等匹配或清晰的规则列举）

有两种写法：直接匹配值，或者写条件表达式。

SQL

```sql
-- 方式一：直接匹配值
CASE status_code
    WHEN 1 THEN SET status_name = 'Pending';
    WHEN 2 THEN SET status_name = 'Processing';
    ELSE SET status_name = 'Unknown';
END CASE;

-- 方式二：搜索条件（类似 IF）
CASE 
    WHEN score >= 90 THEN SET grade = 'A';
    WHEN score >= 60 THEN SET grade = 'B';
    ELSE SET grade = 'C';
END CASE;
```

### 2. 循环结构：`WHILE`、`LOOP`、`REPEAT`

#### `WHILE` 循环（先判断条件，再执行）

**最常用**的循环方式。只要条件为真，就会一直执行。

SQL

```sql
SET i = 1;
WHILE i <= 5 DO
    -- 循环体逻辑
    SET i = i + 1;
END WHILE;
```

#### `REPEAT` 循环（先执行一次，再判断条件）

类似于 C/Java 中的 `do-while`。**至少会执行一次**，直到 `UNTIL` 条件为真时退出（注意：`UNTIL` 后面的条件没有分号）。

SQL

```sql
SET i = 1;
REPEAT
    -- 循环体逻辑
    SET i = i + 1;
UNTIL i > 5 END REPEAT;
```

#### `LOOP` 循环（无条件死循环 + 手动跳出）

需要配合 **标签（Label）** 和 `LEAVE`（相当于 `break`）或 `ITERATE`（相当于 `continue`）使用。适合更复杂的循环控制。

SQL

```sql
SET i = 1;
my_loop: LOOP
    IF i > 5 THEN
        LEAVE my_loop; -- 条件满足时跳出循环
    END IF;

    -- 循环体逻辑
    SET i = i + 1;
END LOOP my_loop;
``````


# 8.存储过程和函数区别（面试重点）

|区别|存储过程|函数|
|---|---|---|
|返回值|可以没有|必须有|
|调用方式|CALL|SELECT|
|参数|IN/OUT/INOUT|只能IN|
|用途|完成业务操作|计算返回结果|
|事务|支持|限制较多|

例如函数：

```
SELECT NOW();
```

存储过程：

```
CALL create_order();
```

# 9. 面试常问

### Q1：为什么企业不用存储过程？

答：

现在互联网项目中：

- 业务变化快
- SQL维护困难
- 数据库压力大
- 不方便版本管理

所以：

> 大多数 Java 项目更倾向于将业务逻辑放在 Service 层，而不是存储过程中。

---

### Q2：存储过程有什么缺点？

## ① 难维护

业务：

```
Java代码
+
SQL
+
存储过程
```

分散。

---

## ② 不利于迁移

MySQL：

```
CREATE PROCEDURE
```

换 Oracle：

语法不同。

---

## ③ 占用数据库资源

大量复杂存储过程：

数据库压力增加。
