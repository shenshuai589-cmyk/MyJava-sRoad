索引设计的目标：

> **提高查询效率，同时控制索引数量和维护成本。**

索引不是越多越好，合理设计才能发挥作用。

---

# 1. 为高频查询字段建立索引

经常出现在：

- `WHERE`
- `ORDER BY`
- `GROUP BY`
- `JOIN`

中的字段，可以考虑建立索引。

例如：

用户表：

```
CREATE TABLE user(
    id BIGINT PRIMARY KEY,
    username VARCHAR(50),
    age INT,
    status INT
);
```

经常查询：

```
SELECT *
FROM user
WHERE username='zhangsan';
```

建立：

```
CREATE INDEX idx_username
ON user(username);
```

---

# 2. 区分度高的字段适合建立索引

索引选择性：

> 不同值数量 / 总记录数

公式：

```
选择性 = COUNT(DISTINCT column) / COUNT(*)
```

选择性越高，查询效率越好。

---

例如：

用户表100万数据：

## username

```
100万个用户
100万个不同名字
```

选择性：

```
100%
```

适合索引。

---

## gender

```
男
女
```

选择性：

```
2 / 1000000
```

不适合单独建立索引。

因为：

查询：

```
WHERE gender='男'
```

可能返回50万数据。

索引效果很差。

---

# 3. 对较长字符串字段使用前缀索引

例如：

```
url VARCHAR(1000)
```

直接建立：

```
CREATE INDEX idx_url
ON website(url);
```

索引空间很大。

可以：

```
CREATE INDEX idx_url
ON website(url(20));
```

只索引前20个字符。

---

# 4. 尽量使用联合索引，减少单列索引

例如：

查询：

```
SELECT *
FROM user
WHERE age=20
AND status=1;
```

不要：

```
age索引
status索引
```

两个单列索引。

推荐：

```
CREATE INDEX idx_age_status
ON user(age,status);
```

优势：

- 一个索引满足查询
- 减少索引数量
- 支持覆盖索引

---

# 5. 联合索引遵循最左匹配原则

例如：

建立：

```
CREATE INDEX idx_a_b_c
ON user(a,b,c);
```

可以支持：

```
WHERE a=1
```

✅

```
WHERE a=1 AND b=2
```

✅

```
WHERE a=1 AND b=2 AND c=3
```

✅

但是：

```
WHERE b=2
```

❌

```
WHERE c=3
```

❌

原因：

B+树按照：

```
a → b → c
```

排序。

---

# 6. 索引字段尽量不要参与计算

错误：

```
SELECT *
FROM user
WHERE id+1=10;
```

因为：

索引列发生计算。

MySQL无法使用索引。

正确：

```
SELECT *
FROM user
WHERE id=9;
```

---

# 7. 避免索引失效

## 不要对索引列使用函数

错误：

```
WHERE YEAR(create_time)=2026
```

正确：

```
WHERE create_time >= '2026-01-01'
AND create_time < '2027-01-01'
```

---

## 不要发生隐式类型转换

例如：

字段：

```
phone VARCHAR(20)
```

错误：

```
WHERE phone=13800138000
```

因为数字转换字符串。

正确：

```
WHERE phone='13800138000'
```

---

## 不要使用左模糊查询

错误：

```
LIKE '%abc'
```

索引失效。

可以：

```
LIKE 'abc%'
```

---

# 8. 控制索引数量

不是越多越好。

原因：

## 增加存储空间

每个索引都是一棵B+树。

## 降低写入性能

INSERT：

```
插入数据
 |
更新主表
 |
更新所有索引
```

索引越多：

写入越慢。

## 增加维护成本

UPDATE、DELETE也需要维护索引。

---

# 9. 经常排序的字段建立索引

例如：

商品列表：

```
SELECT *
FROM product
ORDER BY create_time DESC;
```

建立：

```
CREATE INDEX idx_create_time
ON product(create_time);
```

可以避免：

```
查询数据
 ↓
文件排序
```

---

# 10. 分页查询优化

错误：

```
SELECT *
FROM user
LIMIT 100000,20;
```

MySQL需要：

```
扫描100020条
丢弃100000条
返回20条
```

优化：

利用索引：

```
SELECT *
FROM user
WHERE id > 100000
LIMIT 20;
```

---

# 11. 不适合建立索引的字段

## ① 数据量小的表

例如：

```
系统配置表
几十条数据
```

全表扫描更快。

---

## ② 区分度低字段

例如：

```
性别
状态
是否删除
```

单独建立意义不大。

---

## ③ 经常变化字段

例如：

```
实时状态
频繁更新字段
```

维护成本高。

---

# 12. 索引设计口诀（面试）

> **高频查询建索引，区分度高效果好；联合索引最优先，遵循最左匹配；避免计算和函数，控制数量少而精。**
