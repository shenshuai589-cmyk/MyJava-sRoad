**行锁就是锁住某一行数据的锁**，也叫**记录锁（Record Lock）**。

相比表锁，行锁的粒度更小，并发性能更高，是 InnoDB 存储引擎的核心锁机制。

例如：

```
update user set money = money - 100 where id = 1;
```

执行这条 SQL 时，InnoDB 不会锁整张 `user` 表，而是：

```
user表

id   name    money
1    张三    1000   ← 加行锁
2    李四    2000
3    王五    3000
```

只有 `id=1` 这一行被锁。

其他事务仍然可以修改：

```
update user set money = money - 100 where id = 2;
```

因为锁的是不同的行。

---

# 1. 行锁的特点

## 优点

### 并发能力强

例如：

事务A：

```
update user set money=900 where id=1;
```

锁：

```
id=1
```

事务B：

```
update user set money=1900 where id=2;
```

锁：

```
id=2
```

两个事务可以同时执行。

---

## 缺点

### 加锁成本高

因为需要维护更多锁信息。

比如：

表锁：

```
user
 |
 一个锁
```

行锁：

```
user

id=1  一个锁
id=2  一个锁
id=3  一个锁
...
id=10000 一个锁
```

大量数据操作时，行锁管理成本更高。

# 2. 行锁是 InnoDB 特有的吗？

是。

MySQL 常见存储引擎：

|存储引擎|行锁|
|---|---|
|InnoDB|支持|
|MyISAM|不支持|

MyISAM 只有：

```
表锁
```

所以：

- 查询多
- 写入少

以前 MyISAM 很流行。

现在互联网项目基本：

```
InnoDB
+
行锁
```

# 3. 行锁分类（重点）

InnoDB 行锁主要分三类：

## ① Record Lock（记录锁）

锁住某一条记录。

例如：

```
select * 
from user
where id = 10
for update;
```

锁：

```
id=10
```

别人不能修改：

```
update user 
set name='李四'
where id=10;
```

会等待。

---

## ② Gap Lock（间隙锁）

锁住一个范围，但是不包括记录本身。

例如：

表：

```
id

10
20
30
```

执行：

```
select *
from user
where id > 10 and id < 20
for update;
```

锁：

```
10 --------20

   ↑
 间隙
```

目的：

防止别人插入。

例如事务B：

```
insert into user(id)
values(15);
```

会阻塞。

因为：

```
10---20之间不能插入数据
```

---

## ③ Next-Key Lock（临键锁）

= 记录锁 + 间隙锁

MySQL默认使用。

例如：

数据：

```
10
20
30
```

执行：

```
select *
from user
where id>=10 and id<=20
for update;
```

锁：

```
[10,20]
```

包括：

```
10记录
20记录
10~20之间间隙
```

# 4. 行锁什么时候产生？

## ① UPDATE

自动加行锁：

```
update user
set money=money-100
where id=1;
```

锁：

```
id=1
```

---

## ② DELETE

```
delete from user
where id=1;
```

锁：

```
id=1
```

---

## ③ SELECT FOR UPDATE

主动加锁：

```
select *
from user
where id=1
for update;
```

作用：

查询同时锁定数据。

常用于：

库存扣减：

```
begin;

select stock
from product
where id=1
for update;

update product
set stock=stock-1
where id=1;

commit;
```

防止：

```
两个用户同时购买最后一个商品
```

---

# 5. 行锁什么时候会升级成表锁？

严格来说 InnoDB **不会简单升级成表锁**。

但是以下情况可能导致锁范围扩大。

## 情况1：没有索引

例如：

表：

```
user

id
name
```

执行：

```
update user
set money=100
where name='张三';
```

但是：

```
name没有索引
```

数据库只能：

```
扫描全部数据
```

于是：

可能锁住大量记录。

效果类似：

```
表被锁
```

---

## 情况2：索引失效

例如：

有索引：

```
id
```

但是：

```
where id+1=10
```

导致索引失效。

可能锁更多数据。

---

# 6. 行锁和索引的关系（面试重点）

一句话：

> InnoDB 的行锁是通过锁住索引实现的。

例如：

表：

```
user

id(PK)
name
age
```

SQL：

```
update user
set age=20
where id=1;
```

执行：

```
找到主键索引
       |
       ↓
锁住 id=1 的索引记录
       |
       ↓
找到数据
```

所以：

**没有索引，就无法精准锁行。**

---

# 7. 行锁造成的问题

## ① 死锁

两个事务互相等待。

事务A：

```
update user
set money=100
where id=1;
```

锁：

```
id=1
```

然后：

```
update user
set money=200
where id=2;
```

等待 id=2

---

事务B：

```
update user
set money=300
where id=2;
```

锁：

```
id=2
```

然后：

```
update user
set money=400
where id=1;
```

等待 id=1

形成：

```
A 等 B

B 等 A
```

死锁。

MySQL 会自动回滚一个事务。

---

# 8. 面试总结版

### 什么是行锁？

> 行锁是 InnoDB 对单条记录加的锁，可以提高并发性能。

### InnoDB 行锁有哪些？

```
Record Lock
记录锁

Gap Lock
间隙锁

Next-Key Lock
临键锁
```

### 行锁什么时候失效？

> 当 SQL 没有走索引时，可能锁住大量数据，导致并发降低。

### 行锁和索引关系？

> InnoDB 的行锁锁的是索引记录，而不是直接锁数据行。

### 如何避免行锁问题？

1. 合理设计索引
2. SQL 必须走索引
3. 缩小事务范围
4. 避免事务中执行耗时操作
5. 固定访问顺序避免死锁
