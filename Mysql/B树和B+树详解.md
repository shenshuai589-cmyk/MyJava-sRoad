# B树和B+树详解

B树（B-Tree）和B+树（B+ Tree）是数据库索引的核心数据结构，尤其是 MySQL
InnoDB 的索引，本质上就是 B+树。

它们主要解决一个问题：

> 数据量太大，不能全部放入内存，需要减少磁盘 IO 次数。

------------------------------------------------------------------------

# 一、为什么不用二叉树？

普通二叉搜索树：

``` text
        50
       /  \
     30    70
    / \    / \
  10 40 60 90
```

一次只能分两个方向。

当数据量达到：

``` text
1000万条数据
```

树高度会变得很高。

查询过程：

``` text
磁盘读取
 ↓
节点1
 ↓
节点2
 ↓
节点3
...
```

磁盘 IO 次数增加。

所以数据库需要：

> 一个节点里面存储更多数据，让树的高度降低。

于是出现了 B树。

------------------------------------------------------------------------

# 二、B树（B-Tree）

B树是一种多路平衡搜索树。

一个节点可以存储多个 key：

``` text
              [30 60]

            /    |    \

        <30   30~60   >60
```

一个节点：

``` text
key1 | key2 | key3
```

可以拥有多个子节点。

例如：

``` text
                 [50 100]

             /      |       \

       [10 20] [60 80] [120 150]
```

B树特点：

1.  一个节点可以存多个 key
2.  一个节点可以有多个孩子
3.  所有叶子节点高度一致
4.  数据可以存储在任意节点

------------------------------------------------------------------------

# 三、B树结构示例

``` text
              [50]

          /          \

      [20]          [80]

     /   \          /   \

 [10] [30]     [70] [90]
```

B树中：

数据：

``` text
key + value
```

可以存储在：

-   根节点
-   中间节点
-   叶子节点

例如：

``` text
[50, 用户张三]
```

节点本身就保存数据。

------------------------------------------------------------------------

# 四、==B+树（重点）==

B+树是在B树基础上的优化。

最大的区别：

## 1. B树

所有节点都可以存数据：

``` text
          [50,张三]

       /          \

 [20,李四]      [80,王五]
```

------------------------------------------------------------------------

## 2. B+树

非叶子节点只存索引：

``` text
              [50]

          /          \

      [20]          [80]
```

真正的数据全部存储在叶子节点：

``` text
[20,李四] -> [50,张三] -> [80,王五]
```

------------------------------------------------------------------------

# 五、B树和B+树区别

  区别           B树            B+树
  -------------- -------------- ----------------
  数据存储位置   所有节点       只有叶子节点
  非叶子节点     存数据和索引   只存索引
  叶子节点       没有链表       有链表
  查询           可能提前结束   一定查询到叶子
  范围查询       较慢           非常快
  数据库使用     较少           大量使用

------------------------------------------------------------------------

# 六、为什么MySQL使用B+树？

## 1. 非叶子节点不存数据

MySQL一个数据页大小通常为16KB。

如果节点同时存：

``` text
索引 + 数据
```

那么一个节点存储的 key 数量较少。

如果只存：

``` text
索引
```

则可以存储更多 key。

结果：

``` text
节点存储更多索引
        ↓
树高度降低
        ↓
磁盘IO减少
        ↓
查询速度提高
```

------------------------------------------------------------------------

## 2. 支持范围查询

例如：

``` sql
select *
from user
where id between 100 and 200;
```

B+树叶子节点：

``` text
100
 |
110
 |
120
 |
130
 |
...
 |
200
```

因为叶子节点通过链表连接：

``` text
100 → 110 → 120 → 130 → ...
```

所以范围查询效率非常高。

------------------------------------------------------------------------

# 七、MySQL InnoDB索引为什么是B+树？

例如用户表：

``` text
user

id
name
age
```

创建索引：

``` sql
create index idx_id on user(id);
```

形成：

``` text
                [50]

          /            \

      [20]             [80]


叶子节点：

[20 数据地址]
        ↓
[50 数据地址]
        ↓
[80 数据地址]
```

查询：

``` sql
select *
from user
where id = 50;
```

过程：

``` text
根节点
 ↓
找到索引50
 ↓
进入叶子节点
 ↓
找到真实数据
```

时间复杂度：

``` text
O(logN)
```

------------------------------------------------------------------------

# 八、为什么叫B+树？

B+树相比B树主要增强：

## ① 数据全部存放在叶子节点

方便统一管理。

## ② 叶子节点形成链表

例如：

``` text
[10]
 |
[20]
 |
[30]
 |
[40]
```

可以快速进行：

-   范围查询
-   排序查询
-   分页查询

------------------------------------------------------------------------

# 九、Java后端面试回答模板

面试问题：

> 为什么MySQL索引用B+树？

回答：

> MySQL
> InnoDB索引采用B+树结构，因为B+树的非叶子节点只存储索引，不存储数据，因此一个节点可以存储更多索引，从而降低树的高度，减少磁盘IO次数。同时B+树的叶子节点通过链表连接，方便范围查询和排序查询。
