# Hash索引（Hash Index）

Hash索引也是数据库索引的一种，它通过**哈希表（Hash Table）**实现。

核心思想：

> 将索引字段经过哈希函数计算，生成一个哈希值，然后根据哈希值快速定位数据。

例如：

用户表：

  id   name   age
  ---- ------ -----
  1    张三   20
  2    李四   25
  3    王五   30

给 id 创建 Hash 索引：

``` text
Hash函数：

1 ---> 1001
2 ---> 2034
3 ---> 5678
```

索引结构：

``` text
Hash表

1001 ------> 数据地址1

2034 ------> 数据地址2

5678 ------> 数据地址3
```

查询：

``` sql
select *
from user
where id = 2;
```

过程：

``` text
id=2
 |
Hash函数计算
 |
2034
 |
直接找到数据
```

平均时间复杂度：

``` text
O(1)
```

------------------------------------------------------------------------

# 一、Hash索引结构

简单理解：

``` text
Hash表

key          value

1001  ---> 地址A

2034  ---> 地址B

5678  ---> 地址C
```

其中：

-   key：Hash函数计算后的值
-   value：数据存储位置

------------------------------------------------------------------------

# 二、Hash索引优点

## 1. 查询速度快

因为通过 Hash 可以直接定位。

B+树：

``` text
根节点
 ↓
第二层
 ↓
叶子节点
 ↓
数据

O(logN)
```

Hash：

``` text
key
 ↓
Hash计算
 ↓
数据

O(1)
```

所以：

> 等值查询 Hash 索引理论上更快。

------------------------------------------------------------------------

## 2. 结构简单

B+树：

``` text
索引节点
叶子节点
链表
```

Hash：

``` text
Hash表
```

结构更加简单。

------------------------------------------------------------------------

# 三、Hash索引缺点（重点）

## 1. 不支持范围查询

例如：

``` sql
select *
from user
where id > 100;
```

Hash后：

``` text
100 -> abc
101 -> xyz
102 -> qwe
```

没有顺序：

``` text
abc
xyz
qwe
```

无法快速查询：

``` text
100 ~ 200
```

而B+树：

``` text
100 →101→102→103→...
```

可以快速扫描。

------------------------------------------------------------------------

## 2. 不支持排序

例如：

``` sql
order by id
```

B+树叶子节点：

``` text
10
20
30
40
```

天然有序。

Hash：

``` text
30
10
40
20
```

没有顺序。

------------------------------------------------------------------------

## 3. 不支持联合索引的最左匹配

例如联合索引：

``` text
(name, age)
```

B+树：

支持：

``` sql
where name='张三'
```

也支持：

``` sql
where name='张三'
and age=20
```

Hash：

需要完整 Key：

``` text
Hash(name,age)
```

缺少字段：

``` text
Hash无法计算
```

所以无法使用。

------------------------------------------------------------------------

## 4. Hash冲突问题

不同数据可能产生相同Hash值：

例如：

``` text
张三

Hash:

100


李四

Hash:

100
```

产生：

``` text
Hash冲突
```

解决方式：

## 链地址法

``` text
100

 |
 +--张三

 |
 +--李四
```

但是冲突越多，查询效率越低。

------------------------------------------------------------------------

# 四、MySQL支持Hash索引吗？

## MySQL InnoDB默认不支持Hash索引

InnoDB：

``` text
默认索引结构：

B+树
```

原因：

数据库查询不仅需要：

-   等值查询
-   范围查询
-   排序查询
-   分页查询
-   联合查询

B+树更加适合。

------------------------------------------------------------------------

# 五、MySQL中的Hash索引

## 1. Memory存储引擎

MySQL Memory：

``` text
支持Hash索引
```

例如：

``` sql
CREATE TABLE test(
 id INT,
 INDEX(id) USING HASH
);
```

------------------------------------------------------------------------

## 2. InnoDB自适应Hash索引

虽然InnoDB不用Hash索引作为普通索引。

但是：

> InnoDB存在 Adaptive Hash Index（自适应Hash索引）。

结构：

``` text
        B+树

          |
          |

        热点数据

          |
          ↓

      Hash索引
```

作用：

如果某些数据经常被访问：

例如：

``` sql
select *
from user
where id=100;
```

InnoDB发现：

``` text
id=100
访问次数很多
```

会自动建立Hash结构。

之后：

``` text
查询
 ↓
Hash
 ↓
快速定位B+树节点
```

提高查询效率。

注意：

``` text
这是InnoDB自动维护的，
用户不能手动创建。
```

------------------------------------------------------------------------

# 六、Hash索引 vs B+树索引

  对比           Hash索引   B+树索引
  -------------- ---------- --------------
  数据结构       哈希表     多路平衡树
  查询方式       Hash定位   树查找
  等值查询       非常快     快
  范围查询       不支持     支持
  排序           不支持     支持
  模糊查询       不支持     部分支持
  联合索引       较差       支持最左匹配
  MySQL InnoDB   默认不用   默认使用

------------------------------------------------------------------------

# 七、面试回答模板

问题：

> 为什么MySQL不用Hash索引，而使用B+树？

回答：

> Hash索引虽然在等值查询时效率很高，可以达到O(1)，但是它不支持范围查询、排序查询以及联合索引的最左匹配原则。而数据库业务中除了等值查询，还存在大量范围查询、排序和分页操作，因此MySQL
> InnoDB选择B+树作为默认索引结构。

------------------------------------------------------------------------

# 八、MySQL索引体系

``` text
索引
 |
 +-- B+树索引（InnoDB默认）
 |
 +-- Hash索引
 |
 +-- 全文索引
 |
 +-- 空间索引


重点：

B+树
 ↓
聚簇索引
 ↓
二级索引
 ↓
联合索引
 ↓
最左匹配
 ↓
索引失效
```
