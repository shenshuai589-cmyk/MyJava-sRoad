锁是数据库保证**数据一致性和并发安全**的重要机制。

简单理解：

> **锁是数据库协调多个事务并发访问共享资源的一种机制，用于保证数据一致性和隔离性。**

当多个事务同时修改同一条数据时，如果没有锁：

例如库存：

```
商品库存 = 1

事务A购买：
查询库存=1

事务B购买：
查询库存=1

事务A扣减库存
事务B也扣减库存

库存出现错误
```

所以数据库需要通过锁控制并发。

---

# 二、为什么需要锁？（并发问题）

## 1. 脏读

一个事务读取另一个事务**未提交的数据**。

事务A：

```
UPDATE account
SET money=500
WHERE id=1;
```

未提交。

事务B：

```
SELECT money
FROM account
WHERE id=1;
```

读取500。

事务A：

```
ROLLBACK;
```

实际：

```
money=1000
```

事务B读到了不存在的数据。

---

## 2. 不可重复读

同一个事务，两次读取同一数据结果不同。

事务A：

```
SELECT money FROM account;
```

结果：

```
1000
```

事务B修改：

```
UPDATE account
SET money=500;
```

事务A再次查询：

```
500
```

---

## 3. 幻读

同一个事务查询的数据行数发生变化。

事务A：

```
SELECT *
FROM user
WHERE age>20;
```

结果：

```
10条
```

事务B：

```
INSERT INTO user VALUES(...);
```

事务A再次查询：

```
11条
```

# 四、全局锁

## 作用

锁住整个数据库。

执行：

```
FLUSH TABLES WITH READ LOCK;
```

效果：

整个数据库：

```
只能读取
不能修改
```

释放：

```
UNLOCK TABLES;
```

## 使用场景

数据库备份。

缺点：

- 影响业务
- 并发能力低

# 六、MDL锁（Metadata Lock，元数据锁）

## 1、什么是MDL锁？

MDL锁是 **MySQL为了保护表结构元数据而自动加的锁**。

简单理解：

> **防止一个事务查询表的时候，另一个事务修改表结构。**

因为修改表结构会影响正在执行的SQL。

例如：

表：

```
user

id
name
age
```

事务A正在查询：

```
BEGIN;

SELECT *
FROM user;
```

如果事务B直接修改表结构：

```
ALTER TABLE user
ADD phone VARCHAR(20);
```

那么：

- 事务A看到的表结构是什么？
- 结果集如何返回？

所以MySQL需要保护表结构。

---

# 2、MDL锁分类

MDL主要分：

```
MDL锁
│
├── MDL读锁（MDL_SHARED_READ）
│
└── MDL写锁（MDL_EXCLUSIVE）
```

---

# 2.1. MDL读锁

## 什么时候产生？

执行：

```
SELECT
```

查询表数据时。

例如：

```
BEGIN;

SELECT *
FROM user;
```

事务持有：

```
MDL读锁
```

---

## MDL读锁特点

多个事务可以同时拥有。

例如：

事务A：

```
SELECT *
FROM user;
```

事务B：

```
SELECT *
FROM user;
```

可以：

```
A: MDL读锁
B: MDL读锁

✅ 共存
```

---

# 2. MDL写锁

## 什么时候产生？

修改表结构：

```
ALTER TABLE
DROP TABLE
CREATE INDEX
```

例如：

```
ALTER TABLE user
ADD age INT;
```

需要：

```
MDL写锁
```

---

## MDL写锁特点

排他。

不能和其他MDL锁共存：

```
MDL写锁

不能:
    MDL读锁
    MDL写锁
```

## 3、MDL锁兼容关系（面试重点）

读锁在执行增删改的操作时，是可以的
读锁在执行alter语句时，会发生阻塞，读锁不支持MDL写锁

# 四、MDL锁什么时候释放？

这是重点。

MDL锁：

> **事务提交后才释放**

不是SQL执行结束释放。

例如：

事务A：

```
BEGIN;

SELECT *
FROM user;
```

查询结束。

但是：

```
COMMIT;
```

之前：

MDL读锁仍然存在。

---

事务B：

```
ALTER TABLE user ADD age INT;
```

会等待。


# 5、经典面试案例：为什么线上DDL会阻塞？

例如：

用户表：

1000万数据。

线上执行：

```
ALTER TABLE user
ADD COLUMN phone VARCHAR(20);
```

突然发现：

一直卡住。

原因：

有事务没有提交。

例如：

事务A：

```
BEGIN;

SELECT *
FROM user;
```

忘记：

```
COMMIT;
```

持有：

```
MDL读锁
```

事务B：

```
ALTER TABLE user ADD phone VARCHAR(20);
```

需要：

```
MDL写锁
```

冲突：

```
MDL读锁
    +
MDL写锁

阻塞
```


# 意向锁

# 一、先理解一个问题：为什么需要意向锁？

假设一张表：

```
user表

id   name
1    张三
2    李四
3    王五
```

现在：

事务A想锁住其中一行：

```
SELECT *
FROM user
WHERE id=1
FOR UPDATE;
```

这会给：

```
id=1 这一行
```

加 **行写锁（X锁）**。

此时：

```
user表

id=1  🔒
id=2
id=3
```

---

这时候来了事务B：

它想：

```
LOCK TABLE user WRITE;
```

也就是：

> 我要锁整张user表，别人都不能操作。

问题来了：

MySQL怎么知道：

> 这张表里面有没有行被锁？

---

## 如果没有意向锁

MySQL只能：

```
检查user表每一行
      ↓
发现id=1被锁
      ↓
知道不能加表锁
```

如果一张表有几千万行：

效率非常低。

---

# 二、意向锁的作用

意向锁就是：

> 在给某一行加锁之前，先在表上做一个标记，告诉别人：“这张表里面已经有人加行锁了”。

相当于：

**提前打招呼。**

---

例如：

事务A：

```
SELECT *
FROM user
WHERE id=1
FOR UPDATE;
```

实际发生：

第一步：

给表加：

```
IX锁（意向排他锁）
```

表示：

> 这张表里面有人准备加排他锁

第二步：

给id=1加：

```
X行锁
```

结果：

```
user表

IX锁

id=1  X锁
id=2
id=3
```

---

# 三、为什么叫“意向”？

因为它表达的是：

> 我打算在某些行上加锁。

不是锁住数据本身。

例如：

```
IX

意思：

我这张表里面，
可能有行被X锁锁住
```

---

# 四、意向锁有哪些？

只有两个：

## 1. 意向共享锁（IS）

表示：

> 我准备给某些行加读锁(S锁)

例如：

```
SELECT *
FROM user
WHERE id=1
LOCK IN SHARE MODE;
```

产生：

```
表：
IS锁

行：
S锁
```

---

## 2. 意向排他锁（IX）

表示：

> 我准备给某些行加写锁(X锁)

例如：

```
SELECT *
FROM user
WHERE id=1
FOR UPDATE;
```

产生：

```
表：
IX锁

行：
X锁
```

---

# 五、意向锁和表锁怎么配合？

重点来了：

假设：

事务A：

```
SELECT *
FROM user
WHERE id=1
FOR UPDATE;
```

现在：

```
表：
IX

行：
id=1 X锁
```

事务B：

想：

```
LOCK TABLE user WRITE;
```

需要：

```
表X锁
```

MySQL看到：

```
user表已经有IX锁
```

直接知道：

❌ 不能加表写锁

不用扫描每一行。
