
**触发器是一种特殊的数据库对象，它会在表发生指定操作时，自动执行一段 SQL。**

简单理解：

> **触发器 = 给数据库表绑定一个自动执行的动作**

比如：

- 用户注册 → 自动创建用户积分记录
- 删除订单 → 自动记录删除日志
- 修改商品库存 → 自动更新库存流水

它不需要程序员手动调用，满足条件时数据库自动执行。

# 一、触发器特点

|特点|说明|
|---|---|
|自动执行|不需要手动调用|
|绑定表|属于某一个表|
|由事件触发|INSERT、UPDATE、DELETE|
|不能主动调用|不能像存储过程 CALL|
|可以维护数据一致性|常用于日志、统计|

---

# 二、触发器语法

基本结构：

```
CREATE TRIGGER 触发器名称

触发时间

触发事件

ON 表名

FOR EACH ROW

BEGIN

    SQL语句;

END;
```

---

## 触发时间

两个：

### BEFORE

执行操作之前触发

例如：

```
插入数据
   ↓
触发器执行
   ↓
真正插入
```

---

### AFTER

执行操作之后触发

例如：

```
插入数据
   ↓
真正插入
   ↓
触发器执行
```

---

## 触发事件

三个：

|事件|说明|
|---|---|
|INSERT|插入数据|
|UPDATE|修改数据|
|DELETE|删除数据|

组合：

```
BEFORE INSERT
AFTER INSERT

BEFORE UPDATE
AFTER UPDATE

BEFORE DELETE
AFTER DELETE
```


# 三、创建触发器

## 示例1：新增用户自动创建积分

用户表：

```
CREATE TABLE user(
    id INT PRIMARY KEY,
    username VARCHAR(50)
);
```

积分表：

```
CREATE TABLE user_score(
    id INT,
    score INT
);
```

创建触发器：

```
DELIMITER //

CREATE TRIGGER after_user_insert

AFTER INSERT

ON user

FOR EACH ROW

BEGIN

    INSERT INTO user_score(id,score)
    VALUES(NEW.id,100);

END //

DELIMITER ;
```

执行：

```
INSERT INTO user VALUES(1,'张三');
```

数据库自动执行：

```
INSERT INTO user_score VALUES(1,100);
```

结果：

user：

|id|username|
|---|---|
|1|张三|

user_score：

|id|score|
|---|---|
|1|100|

# 四、NEW 和 OLD（面试重点）

触发器中有两个关键对象：

## NEW

表示**新数据**

用于：

- INSERT
- UPDATE

例如：

```
NEW.name
```

表示新插入的 name。

---

## OLD

表示**旧数据**

用于：

- UPDATE
- DELETE

例如：

```
OLD.salary
```

表示修改前工资。

---

## 不同事件支持情况

|事件|NEW|OLD|
|---|---|---|
|INSERT|✅|❌|
|UPDATE|✅|✅|
|DELETE|❌|✅|

---

# 五、UPDATE触发器案例

需求：

修改员工工资时，记录修改日志。

员工表：

```
employee
```

日志表：

```
salary_log
```

创建：

```
CREATE TRIGGER after_salary_update

AFTER UPDATE

ON employee

FOR EACH ROW

BEGIN

INSERT INTO salary_log(
    emp_id,
    old_salary,
    new_salary
)

VALUES(
    OLD.id,
    OLD.salary,
    NEW.salary
);

END;
```

---

修改：

```
UPDATE employee
SET salary=10000
WHERE id=1;
```

自动生成：

|emp_id|old_salary|new_salary|
|---|---|---|
|1|8000|10000|

# 六、DELETE触发器案例

删除用户时记录日志：

```
CREATE TRIGGER before_user_delete

BEFORE DELETE

ON user

FOR EACH ROW

BEGIN

INSERT INTO delete_log(username)

VALUES(OLD.username);

END;
```

执行：

```
DELETE FROM user
WHERE id=1;
```

自动记录：

```
张三被删除
```

# 九、触发器 vs 存储过程 vs 存储函数（面试）

||触发器|存储过程|存储函数|
|---|---|---|---|
|调用方式|自动触发|CALL调用|SELECT调用|
|返回值|无|可有可无|必须有|
|参数|无|IN/OUT/INOUT|IN|
|绑定对象|表|数据库|数据库|
|执行时机|INSERT/UPDATE/DELETE|主动执行|主动执行|
|用途|自动维护数据|业务流程|计算|



# 触发器缺点（面试常问）

### 1. 隐藏业务逻辑

代码：

```
orderService.create();
```

看不出来数据库还有额外操作。

---

### 2. 调试困难

因为它自动执行。

---

### 3. 性能影响

大量触发器可能导致：

- SQL执行变慢
- 锁竞争增加

---

# 面试回答版

> **MySQL触发器是一种特殊的数据库对象，它绑定在表上，当表执行INSERT、UPDATE、DELETE操作时，会自动触发执行指定SQL。触发器常用于数据一致性维护、日志记录、自动统计等场景。触发器通过NEW和OLD获取新旧数据，其中INSERT只能使用NEW，DELETE只能使用OLD，UPDATE两者都可以使用。**
