

## 一. SQL通用语法

 1. SQL语句可以单行或多行书写，以分号结尾
 2. SQL语句可以使用空格/缩进来增强语句的可读性
 3. MySQL数据库的SQL语句不区分大小写，关键字建议使用大写
 4. 注解：
     单行注解： -- 注解内容 或 # 注解内容
     多行注解：/* 注解内容*/


## 二. SQL分类

| 分类  |             全称             |                          说明 |
| :-- | :------------------------: | --------------------------: |
| DDL |  Data Definition Language  |  数据定义语言，用来定义数据库对象（数据库、表、字段） |
| DML | Data Manipulation Language |     数据操作语言，用来对数据库表中的数据进行增删改 |
| DQL |    Data Query Language     |         数据查询语言，用来查询数据库中表的记录 |
| DCL |   Data Control Language    | 数据控制语言，用来创建数据库用户、控制数据库的访问权限 |

## 五、数值类型


### 5.1 数值类型

| **数据类型**          | **字节数** | **有符号范围 (SIGNED)**               | **无符号范围 (UNSIGNED)**           | **典型应用场景**         |
| ----------------- | ------- | -------------------------------- | ------------------------------ | ------------------ |
| **TINYINT**       | 1 字节    | -128 ~ 127                       | 0 ~ 255                        | 状态标识、开关、年龄         |
| **SMALLINT**      | 2 字节    | -32,768 ~ 32,767                 | 0 ~ 65,535                     | 小规模 ID、端口号         |
| **MEDIUMINT**     | 3 字节    | -8,388,608 ~ 8,388,607           | 0 ~ 16,777,215                 | 中等规模数据量            |
| **INT / INTEGER** | 4 字节    | -2,147,483,648 ~ 2,147,483,647   | 0 ~ 4,294,967,295              | 标准自增主键、常规计数        |
| **BIGINT**        | 8 字节    | -9,223,372,036,854,775,808 ~ ... | 0 ~ 18,446,744,073,709,551,615 | 超大表主键、分布式 ID、用户 ID |
| **FLOAT**         | 4 字节    | 单精度（约 7 位有效数字）                   | 适合科学计算或对精度要求不高的地理坐标、物理数据。      |                    |
| **DOUBLE**        | 8 字节    | 双精度（约 15 位有效数字）                  | 精度比 FLOAT 更高，但仍属于非精确数值。        |                    |
| DECIMAL           |         | 依赖于M(精度)和D(标度)的值                 | 依赖于M(精度)和D(标度)的值               |                    |
> M表示数字的位数，D表示小数部分的长度,如（123.45  M=5,D=2）


### 5.2 字符串类型

| **数据类型**         | **最大长度**                                   | **特点与存储机制**                                                                         | **典型应用场景**                                |
| ---------------- | ------------------------------------------ | ----------------------------------------------------------------------------------- | ----------------------------------------- |
| **CHAR(M)**      | M 个字符（$0 \le M \le 255$）                   | **定长字符串**。不足指定长度时，右侧会补空格；读取时会自动去除末尾空格。存储空间固定。                                       | 长度固定的数据：MD5 密码哈希、手机号、国家代码、身份证号            |
| **VARCHAR(M)**   | M 个字符（理论上限 65,535 字节）                      | **变长字符串**。按实际字符长度加 1-2 字节（记录长度）存储，不占用多余空间。                                          | 长度不固定的短文本：用户名、电子邮件、商品名称、地址                |
| **数据类型**         | **最大存储容量（字节）**                             | **对应 UTF-8 (utf8mb4) 字符估计**                                                         | **典型应用场景**                                |
| **TINYTEXT**     | 255 字节                                     | ~63 个字符                                                                             | 非常短的说明文本                                  |
| **TEXT**         | 65,535 字节 (~64 KB)                         | ~16,383 个字符                                                                         | 博客文章内容、用户评论、产品描述                          |
| **MEDIUMTEXT**   | 16,777,215 字节 (~16 MB)                     | ~419 万字符                                                                            | 大型文章、日志记录、JSON 格式长文本                      |
| **LONGTEXT**     | 4,294,967,295 字节 (~4 GB)                   | ~10 亿字符                                                                             | 极大文档、电子书、代码文件存储                           |
| **数据类型**         | **类型分类**                                   | **说明与对比**                                                                           | **典型应用场景**                                |
| **BINARY(M)**    | 定长二进制                                      | 类似于 `CHAR`，定长，不足会补 `\0` 字节。                                                         | 存储固定长度的二进制哈希或加密密钥                         |
| **VARBINARY(M)** | 变长二进制                                      | 类似于 `VARCHAR`，按实际字节数存储。                                                             | 存储变长的二进制密钥、压缩数据                           |
| **BLOB 系列**      | 大二进制对象                                     | 包括 `TINYBLOB`、`BLOB`、`MEDIUMBLOB`、`LONGBLOB`（容量与 TEXT 对应）。                          | 存储图片、小音频、编译后的文件等（生产环境通常建议存文件系统，数据库仅存 URL） |
| **数据类型**         | **说明**                                     | **示例与限制**                                                                           |                                           |
| **ENUM**         | **单选枚举**。字段只能从预定义的列表中选择**一个**值（内部存为数字索引）。  | `ENUM('small', 'medium', 'large')`<br><br>  <br><br>非常节省空间，但后续修改枚举成员需要 ALTER TABLE。 |                                           |
| **SET**          | **多选集合**。字段可以包含预定义列表中零个或**多个**值的组合（以逗号分隔）。 | `SET('music', 'sports', 'coding')`<br><br>  <br><br>内部按位掩码存储（Bitmask）。              |                                           |


### 5.3 日期类型

|**数据类型**|**格式**|**存储空间**|**范围**|**典型应用场景**|
|---|---|---|---|---|
|**DATE**|`YYYY-MM-DD`|3 字节|`1000-01-01` ~ `9999-12-31`|生日、入职日期、节日|
|**TIME**|`HH:MM:SS`|3 字节|`-838:59:59` ~ `838:59:59`|耗时统计、每日固定营业时间（如 09:00:00）|
|**DATETIME**|`YYYY-MM-DD HH:MM:SS`|5 字节（若带小数秒最多 8 字节）|`1000-01-01 00:00:00` ~ `9999-12-31 23:59:59`|绝对时间记录（如预约时间、历史订单时间）|
|**TIMESTAMP**|`YYYY-MM-DD HH:MM:SS`|4 字节（若带小数秒最多 7 字节）|`1970-01-01 00:00:01` UTC ~ `2038-01-19 03:14:07` UTC|数据修改时间（如 `created_at`、`updated_at`）|
|**YEAR**|`YYYY`|1 字节|`1901` ~ `2155`|出生年份、毕业年份、设备生产年份|


## 六、表操作-修改

> 添加字段

```mysql
alter table 表名 add 字段名 类型（长度）[commit 注释][约束];
```

> 修改数据类型

```mysql
alter table 表名 modify 字段名 新数据类型（长度）;
```

> 修改字段名和字段类型 

```mysql
alter table 表名 change 旧字段名 新字段名 类型（长度）[commit 注释] [约束];
```


> 修改表名

```mysql
alter table 表名 rename to 新表名;
```

## 九、DQL


### 9.1 基本查询

> 1. 查询多个字段

```mysql
select 字段1,字段2,字段3,... from 表名;

select * from 表名;
```

> 2. 设置别名

```mysql
select 字段1 [as 别名1],字段2 [as 别名2],字段3 [as 别名3],...from 表名;
```

>  3.去重复记录

```mysql
select distinct 字段列表 from 表名;
```


### 9.2 条件查序

 ```mysql
 select 字段列表 from 表名 where 条件列表;
 ```



### 9.3 聚合函数

| 函数    | 功能   |
| ----- | ---- |
| count | 统计数量 |
| max   | 最大值  |
| min   | 最小值  |
| avg   | 平均值  |
| sum   | 求和   |
```mysql
select 聚合函数(字段列表) from 表名;
-- null值不参有所有聚合函数运算
```


### 9.4 分组查询

```mysql
select 字段列表 from 表名 [where 条件] group by 分组字段名 [having 分组后过滤条件];
```

> where和having区别

```
执行时机不同：where是分组之前进行过滤，不满足where条件，不参与分组；而having是分组之后对结果进行过滤
判断条件不同：where不能对聚合函数进行判断，而having可以
```


### 9.5 排序查询

```mysql
select 字段列表 from 表名 order by 字段1 排序方式1,字段2,排序方式2;
```

> 排序方式

- ASC：升序（默认）
- DESC：降序


### 9.6 分页查询

```mysql
select 字段列表 from 表名 limit 起始索引,查询记录;
```

```
起始索引从0开始，起始索引=(查询页码 - 1)*每页显示记录数
分页查询是数据库的方言，不同的数据库有不同的实现，mysql中是limit
如果查询的是第一页数据，起始索引可以省略，直接简写为limit 10
```


### 9.7 DQL的执行顺序

```
from 

   表名列表
   
where

   条件列表
   
group by

   分组字段列表

having

   分组后条件列表

select
   
   字段列表

order by

   排序字段列表
   
limit

   分页参数
```

## 十二、约束

| 约束   | 描述                           | 关键字         |
| ---- | ---------------------------- | ----------- |
| 非空约束 | 限制该字段的数据不能为null              | not null    |
| 唯一约束 | 保证该字段的所有数据都是唯一、不重复的          | unique      |
| 主键约束 | 主键是一行数据的唯一标识，要求非空且唯一         | primary key |
| 默认约束 | 保存数据时，如果未指定该字段的值，则采用默认值      | default     |
| 检查约束 | 保证字段满足某一个条件                  | check       |
| 外键约束 | 用来让两张表的数据之间建立连接，保证数据的一致性和完整性 | foreign key |

> 左外连接

```sql

查询表1的所有数据包含表1和表2交际部分的数据
```


>  右外连接

```sql
select 字段列表 from 表1 right join 表2 on 条件...;

查询表2表的所有数据包含表1和表2交际部分的数据
```


### 11.3 联合查询

```sql
select 字段列表 from 表A
union
select 字段列表 fron 表B ...;

对于联合查询的多张表的列数必须保持一致，字段类型也需要保持一致
```
