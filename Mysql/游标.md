## 1. 什么是游标？

**游标（Cursor）是一种用于逐行读取查询结果集的数据库对象。**

简单理解：

> SQL 默认是一次处理一批数据，而游标可以像 Java 的 `Iterator` 一样，一条一条遍历数据。

例如：

Java：

```
for(User user : userList){
    // 一条一条处理用户
}
```

MySQL 游标：

```
FETCH cursor INTO 变量;
```

一次取出一行数据。

---

# 2. 为什么需要游标？

SQL 是集合操作：

例如：

```
UPDATE user
SET status = 1;
```

一次更新所有用户。

但是有些业务需要：

```
用户1 → 执行操作
用户2 → 执行操作
用户3 → 执行操作
...
```

每条数据处理逻辑不同。

这时候可以使用游标。

例如：

订单表：

|id|money|
|---|---|
|1|100|
|2|200|
|3|300|

需求：

根据订单金额计算不同等级：

```
money > 200
高级订单

否则
普通订单
```

需要逐条判断。

# 3. 游标的使用流程（面试重点）

游标一般有四个步骤：

```
① 声明游标
        ↓
② 打开游标
        ↓
③ 获取数据
        ↓
④ 关闭游标
```

对应：

|步骤|关键字|
|---|---|
|声明|DECLARE CURSOR|
|打开|OPEN|
|读取|FETCH|
|关闭|CLOSE|

---

# 4. 游标基本语法

## ① 声明游标

语法：

```
DECLARE 游标名 CURSOR FOR 查询语句;
```

例如：

```
DECLARE user_cursor CURSOR
FOR
SELECT id,name FROM user;
```

表示：

创建一个游标，遍历：

```
SELECT id,name FROM user;
```

---

## ② 打开游标

```
OPEN user_cursor;
```

执行查询：

```
user表数据
      ↓
游标
      ↓
等待读取
```

---

## ③ 获取数据

```
FETCH user_cursor INTO 变量;
```

例如：

```
FETCH user_cursor INTO uid,username;
```

第一次：

```
uid=1
username=张三
```

第二次：

```
uid=2
username=李四
```

---

## ④ 关闭游标

```
CLOSE user_cursor;
```

释放资源。

# 5. 完整案例

假设：

用户表：

```
user

id     name
1      张三
2      李四
3      王五
```

需求：

遍历所有用户。

创建存储过程：

```
DELIMITER //

CREATE PROCEDURE cursor_test()

BEGIN

    -- 定义变量
    DECLARE uid INT;
    DECLARE uname VARCHAR(50);


    -- 定义结束标志
    DECLARE done INT DEFAULT 0;


    -- 声明游标
    DECLARE user_cursor CURSOR FOR
    SELECT id,name FROM user;


    -- 当没有数据时
    DECLARE CONTINUE HANDLER FOR NOT FOUND
    SET done = 1;


    -- 打开游标
    OPEN user_cursor;


    -- 循环读取

    read_loop: LOOP


        FETCH user_cursor 
        INTO uid,uname;


        IF done = 1 THEN

            LEAVE read_loop;

        END IF;


        SELECT uid,uname;


    END LOOP;


    -- 关闭游标

    CLOSE user_cursor;


END //

DELIMITER ;
```

调用：

```
CALL cursor_test();
```

输出：

```
1 张三

2 李四

3 王五
```

# 6. 游标为什么需要 HANDLER？

重点面试问题。

例如：

数据：

```
张三
李四
王五
```

执行：

第一次 FETCH：

```
张三
```

第二次：

```
李四
```

第三次：

```
王五
```

第四次：

没有数据

```


如果没有处理：
```

ERROR

````


所以：

```sql
DECLARE CONTINUE HANDLER FOR NOT FOUND
SET done=1;
````

表示：

> 当游标读取不到数据时，不报错，而是设置结束标志。

# 7. 游标和普通 SQL 的区别

||普通SQL|游标|
|---|---|---|
|处理方式|批量处理|逐行处理|
|效率|高|低|
|适合|大量数据|复杂逐行逻辑|
|资源占用|少|多|

# 9. 游标缺点（面试重点）

## ① 性能差

因为：

```
集合操作
↓
一次完成


游标
↓
循环N次
```

大量数据：

非常慢。

---

## ② 占用资源

游标打开后：

数据库需要维护：

- 结果集
- 当前指针
- 状态

---

## ③ 不符合数据库思想

数据库擅长：

> 集合处理

而游标：

> 模拟程序循环
