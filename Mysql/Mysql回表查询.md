
## 1. 什么是回表查询？

**回表查询指的是：通过普通索引找到主键值后，再根据主键值去聚簇索引中查询完整数据的过程。**

简单理解：

> **普通索引只能找到主键，找到主键后还需要再查一次表，这个过程叫回表。**

---

# 2. 为什么需要回表？

MySQL InnoDB 存储引擎中：

- **主键索引（聚簇索引）保存完整数据**
- **普通索引（二级索引）只保存索引字段 + 主键值**

结构如下：

## 聚簇索引（主键索引）

假设用户表：

```
CREATE TABLE user(
    id INT PRIMARY KEY,
    name VARCHAR(20),
    age INT
);
```

主键索引：

```
主键索引(B+树)

        id
        |
----------------
1   张三  20
2   李四  22
3   王五  25
```

叶子节点保存：

```
完整数据
```

---

## 普通索引

创建：

```
CREATE INDEX idx_name ON user(name);
```

索引结构：

```
name索引(B+树)

       name
        |
----------------

李四  id=2

王五  id=3

张三  id=1
```

注意：

普通索引叶子节点保存：

```
索引字段 + 主键id
```

不是完整数据。

---

# 3. 回表查询过程

例如：

```
select *
from user
where name='张三';
```

假设：

name有普通索引：

```
idx_name
```

执行流程：

---

## 第一步：查询普通索引

进入：

```
name索引B+树
```

找到：

```
name='张三'
id=1
```

得到：

```
主键id=1
```

---

## 第二步：根据主键查询聚簇索引

拿着：

```
id=1
```

再次查询：

```
主键索引
```

找到完整数据：

```
id=1
name=张三
age=20
```

这个过程：

就是：

> 回表查询

---

# 4. 图解回表

```
          普通索引

             |
             |
        name='张三'

             |
             |
          得到id=1

             |
             ↓

       主键索引(聚簇索引)

             |
             |
        查询完整数据

             |
             ↓

          返回结果
```

---

# 5. 哪些情况会发生回表？

## 情况1：普通索引查询全部字段

例如：

```
select *
from user
where name='张三';
```

因为：

普通索引只有：

```
name + id
```

没有：

```
age
```

所以需要回表。

---

## 情况2：查询非索引字段

例如：

索引：

```
(name)
```

查询：

```
select age
from user
where name='张三';
```

普通索引没有age：

需要回表。

---

# 6. 什么情况不会回表？

## 覆盖索引（重点）

如果查询的数据全部在索引中：

不需要回表。

例如：

创建：

```
CREATE INDEX idx_name_age 
ON user(name,age);
```

查询：

```
select name,age
from user
where name='张三';
```

索引中：

```
name
age
id
```

已经包含需要的数据。

所以：

```
普通索引
    |
    |
直接返回结果
```

不需要：

```
普通索引 → 主键索引
```

---

# 7. 覆盖索引优化回表

普通查询：

```
二级索引

↓

获取id

↓

回表

↓

返回数据
```

覆盖索引：

```
二级索引

↓

直接返回数据
```

减少一次IO。

---

# 8. 回表次数问题

例如：

表：

100万数据

SQL：

```
select *
from user
where age=20;
```

如果：

age有普通索引。

可能：

```
age索引
 |
找到10万个id

 |
回表10万次

 |
返回数据
```

大量随机IO。

性能较差。

---

# 9. 如何减少回表？

## 方法1：使用覆盖索引

例如：

原：

```
select *
from user
where name='张三';
```

改：

```
select name
from user
where name='张三';
```

---

## 方法2：避免select *

不要：

```
select *
```

推荐：

```
select id,name
```

只查询需要字段。

---

## 方法3：建立联合索引

例如：

查询：

```
select name,age
from user
where name='张三';
```

建立：

```
create index idx_name_age
on user(name,age);
```

# 10. 回表和索引下推区别（面试常问）

## 回表

流程：

```
二级索引

↓

主键id

↓

聚簇索引

↓

完整数据
```

---

## 索引下推（ICP）

作用：

在索引层提前过滤数据。

例如：

```
select *
from user
where name='张三'
and age=20;
```

没有ICP：

```
找到name

↓

回表

↓

判断age
```

有ICP：

```
索引层判断age

↓

减少回表次数
```

---

# 11. 面试回答模板

**Q：什么是MySQL回表查询？**

答：

> InnoDB中，普通索引的叶子节点只存储索引字段和主键值，不保存完整数据。当通过普通索引查询数据时，需要先找到对应主键，再根据主键去聚簇索引中查询完整记录，这个过程叫回表查询。

---

**Q：如何避免回表？**

答：

> 可以使用覆盖索引，让查询字段全部存在索引中，使MySQL直接从索引返回数据，避免再次访问聚簇索引。
