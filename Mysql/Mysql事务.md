 
### 事务的概念

事务是一组不可分割的 SQL 操作，==要么全部执行成功，要么全部失败回滚==，不会出现只执行一半的情况。


### 事务操作

事务默认情况下是自动提交的

```sql
- 查看/设置事务提交方式
  select @@autocommit;
  
  -- 1为自动提交 0为手动提交
  
  set @@autocommit=0;
  
- 提交事务；
  commit;
  
- 回滚事务
  ROLLBACK;
```


实务操作的方式二

```sql

- 开启事务
start/begin transaction --开启事务

.... 业务逻辑

- 提交事务
commit;

- 回滚事务

ROLLBACK;
```


### 事务的四大特性（ACID）

 - 原子性（Atomicity）：事务是不可分割的最小操作单元，要么全部成功，要么全部失败
 - 一致性（Consistency）:事务执行前后，数据完整性规则不变。转账前后总额不变。
 - 隔离性（Isolation）：多个事务并发执行，彼此互不干扰（由隔离级别控制）。
 - 持久性（Durability）：事务一旦提交或回滚，数据库中的数据的改变是永久的。


### 并发事务问题

- 脏读
- 不可重复读
- 幻读

**1.脏读**
一个事务读到另一个事务还没有提交的数据

**例子：** 你的领导正准备给你发一万元奖金，他在系统里把你的账户余额改成了 $+10000$（未提交）。你这时候去查余额，发现多了万把块钱（脏读）。结果领导突然发现发错人了，取消了操作并回滚。你高高兴兴去取钱，发现根本没这回事。

**2.不可重复读**
同一个事务里，前后两次读取同一条记录，发现内容不一样了侧重于数据被 Update 或 Delete）。

**例子：** 你在网上购物，看中了一件 100 元的衣服（第一次读取）。当你正在犹豫要不要买的这几秒钟里，商家突然把价格改成 150 元并提交了修改（事务 B）。你决定下单付款时，系统再次读取价格发现变成了 150 元（第二次读取）。你一脸懵：刚才明明看的是 100 元啊？


**3.幻读**
同一个事务里，前后两次按相同条件查询，发现记录的“行数”变多了或变少了（侧重于数据被 Insert 或 Delete）。

**例子：** 财务查账，搜索“今天消费大于 1000 元的订单”，一共查到了 5 笔（第一次读取）。此时，某个用户刚好完成了一笔 2000 元的付款（事务 B 插入并提交）。财务接着导出报表，再次查询时发现变成了 6 笔订单（第二次读取）。财务以为自己出现幻觉了。


**不可重复读”与“幻读”的区别**

不可重复读关注的是==某同一条记录==的内容被修改了

幻读关注的是符合条件的记录行数变多了或变少了


### 事务隔离级别


| **隔离级别**                    | **脏读** | **不可重复读** | **幻读** | **常见数据库默认级别**      |
| --------------------------- | ------ | --------- | ------ | ------------------ |
| **读未提交** (Read Uncommitted) | ❌ 会发生  | ❌ 会发生     | ❌ 会发生  | 极少使用               |
| **读已提交** (Read Committed)   | 保持安全   | ❌ 会发生     | ❌ 会发生  | Oracle, SQL Server |
| **可重复读** (Repeatable Read)  | 保持安全   | 保持安全      | ❌ 会发生  | **MySQL (InnoDB)** |
| **串行化** (Serializable)      | 保持安全   | 保持安全      | 保持安全   | 并发极低，很少使用          |

```sql
-- 查看事务隔离级别
select @@transaction_isolation;

-- 设置事务隔离级别
set [session / global] transaction isolation level {read uncommitted | read committeed | repeatable read | serizlizable}

session 表示设置当前会话或窗口的隔离级别

global 所有客户端的会话有效
```
