
## 1. pojo类

### 1.1 实现Serializable接口

pojo类实现Serializable接口的好处：POJO 类实现 `Serializable` 接口，就像是给这个类发了一张“通行证”，告诉 JVM（Java 虚拟机）：“这个类的对象是可以被转换成字节流的。

### 1.2 @NotBlank( message="")

校验注解：这个字段传空字符串或null都会被拦截，配合Controller里的@Valid生效


### 1.3 VO

```

VO = View Object，专门给"查询结果展示"用的对象，跟数据库表不是一一对应关系  
这里是把 Staff 和 Dept 联表查出来的结果揉在一起：既有员工信息，又有部门名称 之所以单独建一个类而不是直接复用Staff/Dept，是因为查询结果的字段组合跟任何一张表都不完全一样  
```


使用VO的好处：

- **保护隐私与安全：** 你的用户表（User Entity）里可能有 `password`（密码哈希）、`salt`（盐值）等敏感字段。如果直接返回实体，这些数据就会暴露给前端。通过 `UserVO`，你可以只暴露 `username`、`nickname` 和 `avatar`。
    
- **节省网络带宽：** 数据库表可能有一百个字段，但前端页面只需要展示其中五个。用 VO 过滤掉无用字段，能极大地减轻网络传输负担。
    
- **数据格式化与适配：** 比如数据库存的是时间戳（`Long`）或创建时间（`LocalDateTime`），而前端需要展示 `"2026-07-15 16:12"` 这种格式。在 VO 中处理这种格式化，可以保持数据库实体干净、纯粹。


## 2. Mapper

常见的mapper方法就是对数据的CRUD（增删改查）
有时还会需要一个方法来对注册时账号是否存在的认证
```java
// 注册时用来判断账号是否存在  
Staff selectByUsername(String username);
```

在sql映射文件（xxxmapper.xml）中，如果有重复的代码可以使用</sql>标签
```java
<sql id="deptColumns">  
    id, dept_name, loc, create_time, update_time
</sql>
  
<select id="selectAll" resultType="Dept">  
    select    
	    <include refid="deptColumns"/>  
    from underworld_dept   
    order by id
</select>     
```

主键自动回填
```xml
<!-- useGeneratedKeys="true" keyProperty="id"：插入后把数据库自动生成的自增id，回填到Java对象dept.id属性上 -->  
<insert id="insert" useGeneratedKeys="true" keyProperty="id">  
    insert into underworld_dept(dept_name, loc, create_time, update_time)    values (#{deptName},#{loc},now(),now())
</insert>
```
