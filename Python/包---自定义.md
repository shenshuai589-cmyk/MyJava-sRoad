
#### 从物理上看，包就是一个文件夹，在该文件夹下包含了一个__init__.py文件，该文件夹可以用来包含多个模块文件，从逻辑上看，包的本质依然是模块


### 什么是包

**包**就是一个包含多个模块（.py 文件）的**文件夹**，用来把相关功能的模块组织在一起，避免所有代码堆在一个目录下混乱不堪。

```
myproject/
├── main.py
└── services/              ← 这是一个包
    ├── __init__.py        ← 标志这个文件夹是包
    ├── user_service.py    ← 模块
    ├── order_service.py   ← 模块
    └── payment_service.py ← 模块
```

### `__init__.py` 的作用

这个文件本身内容可以为空，它的存在就是告诉 Python："这个文件夹是一个包，不是普通文件夹"。

从 Python 3.3 开始有"命名空间包"机制，没有 `__init__.py` 也能被当作包导入，但**正式项目里通常还是保留它**，原因：

- 明确表示这是一个包，可读性好
- 可以在里面写包级别的初始化代码
- 可以配合 `__all__` 控制 `from package import *` 的行为
- 兼容性更好，避免一些奇怪的坑

### 导入包中的模块

python

```python
# 方式一：导入整个模块，用前缀访问
from services import user_service
user_service.create_user()

# 方式二：直接导入某个函数/类
from services.user_service import create_user
create_user()

# 方式三：导入整个包（需要 __init__.py 里有相应设置才好用）
import services
services.user_service.create_user()
```

### 多层嵌套的包

包里还可以再套包，层层组织：

```
myproject/
├── main.py
└── services/
    ├── __init__.py
    ├── user/
    │   ├── __init__.py
    │   ├── register.py
    │   └── login.py
    └── order/
        ├── __init__.py
        └── create_order.py
```

导入方式：

python

```python
from services.user import register
from services.order.create_order import create_order
```

### `__init__.py` 里常见的写法

#### 1. 简化导入路径

python

```python
# services/__init__.py
from .user_service import create_user
from .order_service import create_order
```

这样外部使用时可以直接：

python

```python
from services import create_user  # 不用写 services.user_service
```

#### 2. 配合 `__all__` 控制 `import *`

python

```python
# services/__init__.py
__all__ = ["user_service", "order_service"]  # 只暴露这两个子模块
```

### 包 vs 第三方库（第三方包）

你平时用 `pip install requests` 装的东西，本质上也是**别人写好的包**，发布到了 PyPI（Python 包索引）上。安装后就能像用自己写的包一样 `import requests`。

```
pip install requests      # 从 PyPI 下载并安装
import requests           # 导入使用
```
