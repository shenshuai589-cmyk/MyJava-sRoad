
一个 **模块** 就是一个 `.py` 文件，里面包含函数、类、变量等代码。模块的作用是把代码拆分组织，方便复用和管理，避免所有代码堆在一个文件里。

```
myproject/
├── main.py
├── utils.py      # 这就是一个模块
└── math_tools.py # 这也是一个模块
```

### 导入模块

#### 1. 基本导入


```python
import utils

utils.some_function()  # 通过 "模块名.函数名" 调用
```

#### 2. 导入特定内容


```python
from utils import some_function, SOME_CONSTANT

some_function()  # 直接调用，不用加前缀
```

#### 3. 导入并起别名


```python
import numpy as np
from utils import some_function as sf
```

#### 4. 导入模块中所有内容（不推荐）


```python
from utils import *
```

容易造成命名冲突，不知道某个函数到底从哪来的，正式项目里尽量避免。

### 模块查找路径

导入一个模块时，Python 按以下顺序查找：

1. 当前脚本所在目录
2. `PYTHONPATH` 环境变量指定的目录
3. 标准库目录
4. 第三方包安装目录（`site-packages`）

可以查看搜索路径：


```python
import sys
print(sys.path)
```

### `if __name__ == "__main__"` 的作用


```python
# utils.py
def greet():
    print("Hello")

if __name__ == "__main__":
    greet()  # 只有直接运行 utils.py 时才会执行
```

- 直接运行 `python utils.py` 时，`__name__` 的值是 `"__main__"`，会执行里面的代码。
- 被别的文件 `import utils` 导入时，`__name__` 的值是 `"utils"`，这段代码**不会**执行。

这样可以让一个文件既能被导入复用，又能单独测试运行，是 Python 项目里非常常见的写法。

### 包（Package）：模块的进一步组织

当模块多了，可以用**包**（文件夹）把相关模块归类：

```
myproject/
├── main.py
└── services/
    ├── __init__.py   # 让 Python 把这个文件夹识别成一个包
    ├── user_service.py
    └── order_service.py
```

导入方式：


```python
from services import user_service
from services.order_service import create_order
```

`__init__.py` 在 Python 3.3+ 其实不是必须的（有"命名空间包"机制），但正式项目里通常还是建议保留，明确表示这是一个包，也方便在里面写一些包级别的初始化代码。
