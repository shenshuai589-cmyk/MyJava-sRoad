
当一个函数内部抛出异常且没有被捕获处理时，异常会**沿着调用栈向上传递**，直到被某一层的 `try/except` 捕获，或者一路传到最外层导致程序崩溃。


```python
def func_c():
    raise ValueError("出错了！")  # 异常在这里产生

def func_b():
    func_c()  # 没有 try/except，异常继续向上传

def func_a():
    func_b()  # 同样没有捕获，继续向上传

try:
    func_a()
except ValueError as e:
    print(f"捕获到异常: {e}")  # 最终在这里被捕获
```

**执行流程**：`func_a()` → `func_b()` → `func_c()` 抛出异常 → 沿调用栈反向传递：`func_c` → `func_b` → `func_a` → 最外层的 `try` 捕获。

### 关键点

#### 1. 未捕获的异常会导致程序终止


```python
def risky():
    return 1 / 0  # ZeroDivisionError

risky()  # 没有任何 try/except，程序直接崩溃并打印 traceback
```

#### 2. 可以在任意一层捕获，捕获后传递就此停止

```python
def func_b():
    try:
        func_c()
    except ValueError as e:
        print("在 func_b 里捕获了，不再往上传")
        # 不 re-raise 的话，func_a 感知不到这个异常
```

#### 3. 捕获后可以选择"重新抛出"（re-raise），让异常继续向上传


```python
def func_b():
    try:
        func_c()
    except ValueError as e:
        print("记录一下日志")
        raise  # 重新抛出，继续向上传递给 func_a
```

#### 4. traceback 会记录完整的传递路径

Python 报错时打印的 `Traceback (most recent call last)` 就是异常传递路径的体现，从最初抛出的位置到最终捕获（或崩溃）的位置，每一层调用都会显示出来。

### 类比 Java（既然你在做 Java 后端方向）

这个机制在 Java 里是一样的，区别主要在语法和异常分类：


```java
public class Demo {
    static void funcC() {
        throw new RuntimeException("出错了！");
    }
    static void funcB() {
        funcC(); // 未捕获，继续向上传
    }
    static void funcA() {
        try {
            funcB();
        } catch (RuntimeException e) {
            System.out.println("捕获到异常: " + e.getMessage());
        }
    }
}
```

不同点：

- Java 区分 **checked exception**（受检异常，必须显式声明 `throws` 或捕获）和 **unchecked exception**（运行时异常，可以不处理，自动向上传）。
- Python 的异常全部相当于 Java 的 unchecked exception，不强制要求声明或捕获。

### 实际开发中的意义

异常传递性的价值在于：**你不需要在每一层都写 try/except**，只需要在你真正知道"该怎么处理这个异常"的那一层去捕获它。这样代码更清晰，也避免了"捕获了但不知道怎么处理"的空 catch 块。

比如在 Web 后端里，常见做法是：底层的数据库操作、工具函数不捕获异常，让它自然向上传递，最终在**最外层的统一异常处理器**（比如 Spring 的 `@ControllerAdvice` 或者 Python Web 框架的全局异常处理中间件）里统一捕获、记录日志、返回给客户端友好的错误信息。
