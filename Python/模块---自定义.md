
> 在一个新的python文件中，定义我们享有的函数，在另一个python文件中import导包即可

```python
my_module1.py

def test(a,b):
	print(a+b)
```

```python
import my_module1 as my
my.test(1,2)
```


### 不同包中的同名函数

```python
my_module2.py

def test(a,b):
	print(a-b)
```

假设此时在py文件中调用两个包会怎么样呢？

```python
import my_module1 as my
import my_module2 as my

my.test(1,2) # -1
# 谁后被导包，就用哪个包的函数
```

### 如果我们想要测试函数

```python
my_module2.py

def test(a,b):
	print(a-b)
	
test(1,2)
```

那么此时在另一个py文件中导入该包并运行时，会发现控制台打印了 -1

那么有没有什么方法不这样呢？

```python
my_module2.py

def test(a,b):
	print(a-b)
	
if __name__ == '__main__':
	test(1,2)

```

### `__name__` 与 `"__main__"`

严格来说不是有个叫 `__main__` 的变量，而是每个模块都有一个内置变量 `__name__`，它的值会根据运行方式变化：

python

```python
# demo.py
print(__name__)
```

- **直接运行**该文件（`python demo.py`）→ `__name__` 的值是字符串 `"__main__"`
- **被其他文件 import** 时 → `__name__` 的值是模块名本身，比如 `"demo"`

#### 最常见用法：入口判断

python

```python
def main():
    print("程序开始运行")

if __name__ == "__main__":
    main()
```

**作用**：让这段代码只有在"直接运行这个文件"时才执行，被别人 `import` 时不会自动跑起来。这是 Python 项目里几乎必写的模式，相当于 Java 里的：

java

```java
public static void main(String[] args) { ... }
```

区别是 Java 的 `main` 是语言强制的入口方法，Python 的这个判断只是一种**约定俗成的写法**，不写也能运行脚本，只是不写的话，被 import 时里面所有顶层代码都会被执行一遍（通常不是你想要的）。

### 二、`__all__`

`__all__` 是用来控制 `from module import *` 时，**具体导入哪些名字**的一个列表。

python

```python
# utils.py
def public_func():
    pass

def _private_func():   # 约定：下划线开头表示"内部使用"
    pass

__all__ = ["public_func"]  # 只暴露这一个
```

python

```python
# main.py
from utils import *

public_func()    # ✅ 可以调用
_private_func()  # ❌ NameError，因为没在 __all__ 里
```

#### 关键点

- `__all__` **只影响 `import *` 这种写法**。如果显式写 `from utils import _private_func`，即使不在 `__all__` 里，照样能导入成功，`__all__` 管不住这种情况。
- 通常配合"不推荐用 `import *`"这个原则一起理解：`__all__` 是给 `import *` 划定一个"安全范围"，避免把内部实现细节、临时变量全部暴露出去。
- 包（`__init__.py`）里也常用 `__all__` 来控制 `from package import *` 时暴露哪些子模块。

---

### 对比一句话总结

|变量|作用|生效场景|
|---|---|---|
|`__name__`|判断当前文件是被直接运行还是被导入|单个脚本内部逻辑控制|
|`__all__`|控制 `import *` 时对外暴露哪些名字|模块/包的接口范围控制|
