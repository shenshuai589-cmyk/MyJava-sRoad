
堆的分代（Generational Collection）是 Java 虚拟机（JVM）垃圾回收机制中的一种核心内存管理策略。它将堆内存（Heap）划分为不同的区域，用来存放**不同生存周期**的对象，从而大幅提升垃圾回收（GC）的效率。

**核心依据：弱分代假说（Weak Generational Hypothesis）**

分代设计的理论基础基于两个绝大多数程序都符合的现象：

1. **绝大多数对象都是朝生夕灭的**（例如方法内部的局部变量、临时拼接的字符串）。
    
2. **熬过越多次垃圾回收的对象，越不易死亡**（例如 Spring 管理的 Bean、静态配置、缓存对象）。

**堆内存的具体分代结构**

经典的 JVM 堆内存主要划分为以下两个部分：

- **新生代（Young Generation）**
    
    - **职责**：存放刚被创建的新对象。
        
    - **内部构成**：进一步分为 **Eden 区** 和两个大小相等的 **Survivor 区（S0 / S1 或 From / To）**，默认比例通常为 `8:1:1`。
        
    - **回收特点**：由于绝大部分对象会在 Eden 区迅速死亡，新生代采用**标记-复制算法**。GC 触发频率高、速度极快（称为 **Minor GC / Young GC**）。
        
- **老年代（Old Generation / Tenured）**
    
    - **职责**：存放生命周期较长、多次 GC 后依然存活的对象，或占用空间极大的超大对象。
        
    - **回收特点**：采用**标记-清除算法**或**标记-整理算法**。GC 触发频率较低，但因为对象存活率高、空间大，回收耗时较长（称为 **Major GC / Old GC**）。
        

**为什么要进行堆分代？**

|**未分代（统一扫描）**|**分代管理（按需回收）**|
|---|---|
|每次垃圾回收都需要遍历堆中的**所有对象**。|将高频死亡对象集中在新生代，GC 只需扫描一小块区域。|
|随着堆内存变大，扫描耗时极长，卡顿（STW）明显。|针对不同区域的特点选用最优回收算法，显著提升 GC 性能与响应速度。|

**对象的分代晋升过程**

1. **分配**：新对象优先在 **Eden 区** 分配。
    
2. **复制**：当 Eden 区满触发 Minor GC 时，存活的对象会被复制到 **S0**，年龄记为 1；Eden 区被清空。
    
3. **轮转**：下一次 Minor GC 时，Eden 和 S0 的存活对象被复制到 **S1**，年龄加 1。S0 和 S1 的角色互换（始终保持一个 Survivor 区为空）。
    
4. **晋升（Tenuring）**：当对象的年龄达到阈值（默认为 15，可通过 `-XX:MaxTenuringThreshold` 调整），或满足动态年龄判定规则时，该对象会被移入**老年代**。
