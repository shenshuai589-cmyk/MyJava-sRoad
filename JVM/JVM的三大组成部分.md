### 2.3 JVM Stacks   虚拟机栈


> 虚拟机栈负责保存Java方法执行过程中的栈帧，每调用一个方法，就创建一个栈帧，
> 方法结束，栈帧销毁。


**1. 栈在哪里**

JVM内存结构：

```
JVM运行时数据区


线程共享
-------------------
堆（Heap）
方法区（Method Area）


线程私有
-------------------
程序计数器
虚拟机栈 ⭐
本地方法栈
```

特点:
  - 每个线程都有自己的虚拟机栈
  - 生命周期和线程一致

---

**2. 栈里存放什么**

栈里面存的是：

 **栈帧（Stack Frame）**

每调用一个Java方法：

就创建一个栈帧。

例如：

```
public class Demo {

    public static void main(String[] args){

        method1();

    }


    public static void method1(){

        int a = 10;

    }
}
```

执行过程：

---

进入main：

```
虚拟机栈

| main()栈帧 |
```

---

调用method1：

```
虚拟机栈

| method1()栈帧 |
| main()栈帧    |
```

---

method1执行结束：

```
虚拟机栈

| main()栈帧 |
```

---

main结束：

```
空
```

---

**3. 栈帧结构**

一个栈帧主要包含4部分：

```
栈帧

├── 局部变量表 ⭐
├── 操作数栈 ⭐
├── 动态链接
└── 方法出口
```

### 2.4 PC Register  程序计数器


> 程序计数器记录当前线程下一条要执行的字节码指令地址。


**程序计数器的特点**

   **1. 程序计数器属于线程私有**
   
    JVM内存区域：

```
JVM运行时数据区


线程共享
-----------------
堆
方法区


线程私有
-----------------
程序计数器
虚拟机栈
本地方法栈
```

为什么程序计数器必须线程私有？

因为：

Java支持多线程。

例如：

```
Thread A:

执行:
a=10


Thread B:

执行:
b=20
```

两个线程执行位置不同。

所以：

线程A：

```
PC = 100
```

线程B：

```
PC = 200
```

如果共享：

线程切换后不知道执行到哪里。


****

**2. 程序计数器如何支持线程切换？** 

假设：

线程A：

执行：

```
1
2
3
4
```

执行到：

```
3
```

突然CPU切换：

```
A暂停
↓
B执行
```

程序计数器保存：

```
A:
PC=3
```

B执行：

```
B:
PC=20
```

过一会：

A恢复：

读取：

```
PC=3
```

继续执行：

```
4
```

这就是线程上下文切换。

---

**3. 程序计数器不会OutOfMemoryError**

每个线程只保存一个地址：

例如：

```
0x0000007FFA123456
```

空间非常小。

而且线程结束自动释放。

所以：

> 程序计数器是JVM中唯一不会出现OOM的区域。

---
### Q1：程序计数器有什么作用？

回答：

> 程序计数器用于记录当前线程下一条需要执行的字节码指令地址，在线程切换时，通过保存和恢复程序计数器，实现线程之间的正常执行。

---

### Q2：为什么程序计数器是线程私有？

回答：

> 因为Java支持多线程，每个线程执行的位置不同，需要独立保存自己的执行进度，否则线程切换后无法恢复执行。

---

### Q3：程序计数器会发生OOM吗？

回答：

> 不会，因为程序计数器存储的数据非常小，只保存当前指令地址，而且线程结束后会自动释放。
