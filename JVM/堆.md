
堆是 **JVM运行时数据区域中最重要的一块内存区域**，也是Java后端面试中**JVM最高频考点**。

一句话理解：

> **堆是JVM中用于存放对象实例和数组的内存区域，也是垃圾回收器（GC）主要管理的区域。**

---

# 1. 堆的基本特点

## ① 线程共享

和程序计数器、虚拟机栈不同：

```
线程私有：
----------------
程序计数器
虚拟机栈
本地方法栈


线程共享：
----------------
堆 ⭐
方法区
```

为什么共享？

因为对象需要被多个线程访问。

例如：

```
User user = new User();
```

对象：

```
          堆

       User对象
       {
          id=1
       }


线程A --------
             |
线程B --------
```

多个线程可以引用同一个对象。

# 3. 堆为什么需要分代？

如果所有对象放一起：

```
堆

对象1
对象2
对象3
对象4
...
```

GC效率很低。

因为：

Java对象有一个特点：

> 大部分对象朝生夕死。

例如：

```
public void test(){

    User u=new User();

}
```

方法结束：

```
User对象
|
没有引用
|
垃圾
```

很快死亡。

但是：

比如：

```
static User user=new User();
```

生命周期很长。

所以JVM采用：

# 分代思想

# 4. 堆的内存结构（重点⭐⭐⭐⭐⭐）

传统HotSpot JVM：

```
              Java堆


        老年代 Old Generation
        -------------------
        长期存活对象


        新生代 Young Generation
        -------------------
        新创建对象

             |
     ----------------
     |      |       |
 Eden  Survivor0 Survivor1
```

存：

> 刚创建的对象

例如：

```

```

刚开始：

```
Eden区

User对象
```

---

新生代：

```
Young


Eden

Survivor0

Survivor1
```

比例：

默认：

```
Eden : S0 : S1

8 : 1 : 1
```

# 7. 新生代GC（Minor GC）

当Eden满：

触发：

```
Minor GC
```

例如：

GC前：

```

B
C
D
```

GC：

发现：

```
A B D
还能用

C

```

结果：

```
清除C

A B D

```

# 8. 对象什么时候进入老年代？

对象长期存活。

每经历一次GC：

年龄 +1

例如：

```
第一次GC

年龄=1


第二次GC

年龄=2


...


年龄达到15

进入老年代
```

默认：

```
-XX:MaxTenuringThreshold=15
```

---

# 9. 大对象直接进入老年代

例如：

```
byte[] arr=new byte[100MB];
```

太大。

避免：

```
新生代复制成本太高
```

直接：

```
老年代
```

# 10. 老年代（Old Generation）

存：

> 生命周期长的对象。


缓存：

```
服务器启动

↓

一直存在

↓

老年代
```

```

```

多个线程：

```

线程B 修改
```

需要：

```

Lock
Atomic
```

# 12. 堆可能出现的问题

## ① OutOfMemoryError

例如：

不断创建对象：

```
List list=new ArrayList();

while(true){

    list.add(new User());

}
```

结果：

```
堆空间耗尽

↓

OutOfMemoryError
```

---

## ② 内存泄漏

例如：

对象不用了，但是还有引用：

```
static List list=new ArrayList();

while(true){

 list.add(new User());

}
```

GC认为：

```
还有引用

↓

不能回收
```

最终：

OOM。

# 14. 面试回答版本

面试官：

> JVM堆是什么？

回答：

> JVM堆是Java虚拟机中最大的一块内存区域，用于存放对象实例和数组。堆是线程共享区域，也是垃圾回收器主要管理的区域。HotSpot JVM采用分代设计，将堆划分为新生代和老年代，新创建对象通常进入新生代，长期存活对象进入老年代。
