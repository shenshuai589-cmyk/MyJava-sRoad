

方法区是 **JVM运行时数据区域的重要组成部分**。

一句话理解：

> **方法区用于存储被JVM加载的类信息、静态变量、常量、方法代码等数据。**

它和堆一样：

- 属于**线程共享区域**
- JVM启动时创建
- 生命周期和<a href="D:\CUCN\Markdown\Obsidian Vault\JVM\JVM生命周期.md">JVM的生命周期</a>一致

# 一、类信息（Class Information）

当JVM加载一个类：

例如：

```
public class User {

    private int id;

    public void say(){

        System.out.println("hello");

    }
}
```

JVM加载：

```
User.class

↓

方法区
```

保存：

- 类的全限定名
- 父类信息
- 接口信息
- 字段信息
- 方法信息

例如：

```
User类

父类:
Object

字段:
id

方法:
say()
```

# 二、运行时常量池（Runtime Constant Pool）

这是方法区非常重要的一部分。

什么是常量池？

简单理解：

> 存放编译期间生成的各种字面量和符号引用。

例如：

```
String name = "张三";
```

其中：

```
"张三"
```

就是字符串常量。

---

例如：

```
public class Test {

    public static final int MAX=100;

}
```

常量：

```
MAX
100
```

会进入常量池。

---

## 字符串常量池（容易混淆）

注意：

字符串常量池属于：

```
运行时常量池的一部分
```

但是：

不同JDK版本位置不同。

JDK7以后：

字符串常量池移动到了：

```
堆
```

而不是永久代。

# 3. 方法区和永久代、元空间的关系（面试重点）

很多人容易混。

## Java 7以前

HotSpot：

```
方法区

↓

永久代 PermGen
```

也就是说：

方法区的实现叫永久代。

---

## Java 8以后

取消永久代：

```
方法区

↓

元空间 Metaspace
```

结构：

```
方法区（规范）

       ↓

元空间（HotSpot实现）
```

---

为什么换？

因为永久代：

问题：

- 大小固定
- 容易OOM

例如：

加载大量类：

```
PermGen space

↓

OutOfMemoryError
```

---

元空间：

特点：

- 使用本地内存
- 自动扩容
- 减少OOM风险

# 5. 方法区和堆的区别

面试经常问：

||方法区|堆|
|---|---|---|
|存储|类信息|对象实例|
|线程|共享|共享|
|生命周期|JVM运行期间|对象生命周期|
|GC|较少|频繁|
|实现|元空间|堆内存|

---

举个完整例子：

代码：

```
public class User {

    static int count=0;

    String name;

}

User u=new User();
```

内存：

```
方法区：

User类信息
User方法
static count


        ↓


堆：

User对象
{
 name=null
}


        ↑


栈：

u引用
```

# 7. 面试回答版本

面试官：

> JVM方法区是什么？

回答：

> 方法区是JVM运行时数据区域的一部分，是线程共享的内存区域，主要用于存储类的元数据、运行时常量池、静态变量以及方法字节码等信息。在HotSpot虚拟机中，Java8之后使用元空间实现方法区。
