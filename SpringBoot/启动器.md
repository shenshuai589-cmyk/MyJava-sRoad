# Spring Boot 启动器（Starter）详解

## 1. 什么是 Starter

Starter（启动器）是 Spring Boot 最核心的设计之一。

简单来说：

> Starter 就是一组场景依赖的集合。

开发者只需要引入一个 Starter，Spring Boot 就会自动帮我们引入当前场景所需的大部分依赖。

例如：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

仅需这一项依赖，就能完成 Web 开发环境的搭建。

---

## 2. 为什么需要 Starter

### 2.1 传统 Spring 项目

以前开发 SpringMVC 项目时，需要手动导入很多依赖：

```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-web</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-webmvc</artifactId>
</dependency>

<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
</dependency>

<dependency>
    <groupId>org.apache.tomcat.embed</groupId>
    <artifactId>tomcat-embed-core</artifactId>
</dependency>
```

存在的问题：

- 依赖数量多
    
- 容易遗漏依赖
    
- 容易发生版本冲突
    
- 配置繁琐
    

---

### 2.2 Spring Boot 的解决方案

只需要引入：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Spring Boot 自动完成：

- SpringMVC
    
- Tomcat
    
- JSON转换
    
- 参数校验
    
- Web开发环境
    

的相关依赖导入。

---

## 3. Starter 的本质

Starter 本质上是：

> 一个依赖管理包（Dependency Aggregator）

自身几乎不写业务代码。

例如：

```xml
spring-boot-starter-web
```

内部会依赖：

```text
spring-webmvc
spring-web
jackson-databind
tomcat-embed-core
tomcat-embed-el
validation-api
...
```

其工作流程：

```text
开发者引入 Starter
        ↓
Starter 引入其他依赖
        ↓
Maven 传递依赖机制
        ↓
所有依赖自动下载
```

## 6. Starter 与自动配置的关系

很多人容易把两者混淆。

实际上：

```text
Starter
    ↓
负责导入依赖

AutoConfiguration
    ↓
负责自动配置 Bean
```

例如：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

引入后发生两件事：

### 第一步：导入依赖

```text
SpringMVC
Tomcat
Jackson
```

---

### 第二步：自动配置

Spring Boot 自动创建：

```java
DispatcherServlet
RequestMappingHandlerMapping
ObjectMapper
Tomcat
```

无需手动配置 XML。

---

## 7. Starter 和普通依赖的区别

### 普通依赖

```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-webmvc</artifactId>
</dependency>
```

特点：

- 只导入一个库
    
- 需要手动补充其他依赖
    

---

### Starter

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

特点：

- 导入整个场景所需依赖
    
- 自动配置运行环境
    
- 降低开发复杂度
    

---

## 8. 面试题

### Starter 是什么？

Starter 是 Spring Boot 提供的场景启动器，本质是依赖描述符，能够帮助开发者快速引入某一功能场景所需的全部依赖。

---

### Starter 的作用是什么？

- 简化依赖管理
    
- 统一依赖版本
    
- 减少配置工作
    
- 配合自动配置快速搭建环境
    

---

### Starter 和自动配置有什么区别？

Starter：

```text
负责导入依赖
```

AutoConfiguration：

```text
负责创建Bean
负责自动配置
```

两者配合实现：

```text
开箱即用（Convention over Configuration）
```

---

## 10. 核心总结

```text
Starter 本质：
    一组场景依赖集合

Starter 作用：
    自动导入相关依赖

AutoConfiguration 作用：
    自动创建 Bean

Starter + AutoConfiguration
    =
Spring Boot 开箱即用
```

学习 Spring Boot 时，最重要的问题之一：

为什么引入 spring-boot-starter-web 后，  
Tomcat、SpringMVC、Jackson 都自动拥有了？

答案就是：

Starter + 自动配置机制。
