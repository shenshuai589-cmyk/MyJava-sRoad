## 1. HashMap.put() 源码入口

平时我们使用：

```
map.put(key, value);
```

实际上会进入 `putVal()`：

```
public V put(K key, V value) {
    return putVal(hash(key), key, value, false, true);
}
```

整体流程：

```
map.put(key, value)
        ↓
    hash(key)
        ↓
   计算 hash
        ↓
    putVal()
        ↓
   定位数组桶
        ↓
判断桶是否为空
    ↓           ↓
  为空         不为空
   ↓             ↓
直接插入       处理冲突
                 ↓
            链表 / 红黑树
                 ↓
             插入 / 覆盖
                 ↓
               扩容？
```

# 2. HashMap 的核心数据结构

Java 8 中，HashMap 可以理解为：

```
HashMap
   ↓
Node[]
   ↓
数组
   ↓
┌───────────────┐
│   table[0]    │
│   table[1]    │
│   table[2]    │
│      ...      │
│   table[n]    │
└───────────────┘
```

数组中的每个位置称为一个：

> **桶（bucket）**

一个桶中可能存在：

```
Node
 ↓
Node
 ↓
Node
```

形成链表。

当链表过长时，在满足条件的情况下会转化为：

```
链表
 ↓
红黑树
```

因此可以概括为：

> **HashMap = 数组 + 链表 + 红黑树**

---

# 3. hash(key)

HashMap 在执行 `put()` 时，第一步不是直接计算数组下标，而是先计算 hash。

核心源码：

```
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

---

## 3.1 key 为 null

如果：

```
map.put(null, "张三");
```

那么：

```
key == null
```

成立。

最终：

```
hash = 0
```

所以 HashMap 可以存储：

> **一个 null key**

---

# 4. key 不为 null

如果 key 不为 null：

```
h = key.hashCode();
```

例如：

```
String key = "张三";
```

执行：

```
"张三"
   ↓
hashCode()
   ↓
得到 int 类型 hashCode
```

但是 HashMap 并不会直接使用这个 hashCode。

而是继续进行：

```
h ^ (h >>> 16)
```

这一步叫：

# 扰动函数

---

# 5. 为什么要进行 hash 扰动？

HashMap 后面计算数组下标时，会使用：

```
(n - 1) & hash
```

假设：

```
n = 16
```

那么：

```
n - 1 = 15
```

二进制：

```
15 = 00000000 00001111
```

因此最终计算桶位置时，主要使用 hash 的低位信息。

如果不同 key 的：

```
高位不同
低位相同
```

那么它们可能得到相同的桶位置。

例如：

```
key1：
10101111 00000001

key2：
11001111 00000001
```

虽然高位不同：

```
10101111
11001111
```

但是低位相同：

```
00000001
```

那么在使用低位计算桶下标时，就可能发生冲突。

---

## 5.1 扰动函数的作用

HashMap：

```
h ^ (h >>> 16)
```

将 hashCode 的高 16 位移动到低位：

```
高 16 位
   ↓
右移 16 位
   ↓
参与低位计算
```

再通过异或：

```
h ^ (h >>> 16)
```

让高位的信息也参与到最终 hash 的计算中。

### 面试回答

> HashMap 对 key 的 hashCode 进行扰动，将高 16 位的信息混入低 16 位，使高位信息也能够参与桶下标的计算，从而尽量减少哈希冲突。

---

# 6. HashMap 为什么数组长度通常是 2 的幂？

HashMap 定位桶的位置：

```
(n - 1) & hash
```

例如：

```
n = 16
```

那么：

```
n - 1 = 15
```

二进制：

```
16 = 10000
15 = 01111
```

所以：

```
hash & 01111
```

可以快速得到：

```
0 ~ 15
```

之间的数组下标。

---

## 6.1 与取模运算的关系

例如：

```
hash = 29
n = 16
```

使用：

```
29 % 16
```

结果：

```
13
```

而：

```
29 & (16 - 1)
```

即：

```
29 & 15
```

二进制：

```
  11101
& 01111
-------
  01101
```

结果：

```
13
```

因此：

```
hash % n
```

在 `n` 为 2 的幂的情况下，可以利用：

```
hash & (n - 1)
```

快速得到类似的结果。

---

# 7. 为什么必须是 2 的幂？

因为：

```
2^n - 1
```

的二进制形式具有一个重要特点：

> **低位全部为 1**

例如：

```
2^4 = 16

16 - 1 = 15

15 =
00001111
```

再比如：

```
2^3 = 8

8 - 1 = 7

7 =
00000111
```

因此可以通过：

```
hash & (n - 1)
```

快速计算桶下标。

# 9. 第一次 put：初始化数组

创建：

```
HashMap<String, Integer> map = new HashMap<>();
```

并不会立即创建一个长度为 16 的数组。

可以理解为：

```
new HashMap()
      ↓
table 暂时没有初始化
```

第一次：

```
map.put("张三", 18);
```

才可能进入：

```
resize();
```

初始化数组。

最终：

```
Node[16]
```

# 10. 为什么 resize() 不只是扩容？

`resize()` 有两个重要作用：

### 第一次

```
table 不存在
    ↓
resize()
    ↓
初始化数组
```

### 后续

```
HashMap 达到扩容条件
    ↓
resize()
    ↓
扩容
```

所以：

> **resize() 既负责初始化，也负责扩容。**

# 11. 定位桶

假设：

```
table.length = 16
```

key 的 hash 已经计算出来。

桶下标：

```
int index = (n - 1) & hash;
```

例如：

```
n = 16
hash = 29
```

那么：

```
index = (16 - 1) & 29
      = 15 & 29
      = 13
```

因此：

```
table[13]
```

就是这个 key 应该进入的桶。

---

# 12. 桶为空

假设：

```
index = 5
```

并且：

```
table[5] == null
```

说明：

> 当前桶没有任何节点。

那么直接创建 Node：

```
table[5]
   ↓
Node("张三", 18)
```

示意：

```
table

[0] null
[1] null
[2] null
[3] null
[4] null
[5] Node("张三",18)
[6] null
[7] null
...
[15] null
```

这就是最简单的情况。

# 13. Hash 冲突

现在：

```
map.put("李四", 20);
```

假设：

```
"李四"
 ↓
hash
 ↓
index = 5
```

但是：

```
table[5]
```

已经存在：

```
Node("张三",18)
```

这时候发生：

# Hash 冲突

也就是：

```
张三
 ↓
index = 5

李四
 ↓
index = 5
```

两个不同的 key 被定位到了同一个桶。

---

# 14. HashMap 如何处理 Hash 冲突？

不能直接把原来的节点覆盖掉。

因为：

```
"张三" != "李四"
```

所以可以形成链表：

```
table[5]
   ↓
Node("张三",18)
   ↓
Node("李四",20)
```

继续发生冲突：

```
table[5]
   ↓
张三
   ↓
李四
   ↓
王五
   ↓
赵六
```

---

# 15. 为什么还需要 equals()？

仅仅 hash 相同并不能说明两个 key 相同。

例如：

```
key1
 ↓
hash = 100

key2
 ↓
hash = 100
```

这只是：

> **Hash 冲突**

不能说明：

```
key1.equals(key2)
```

一定为 `true`。

所以 HashMap 的判断逻辑可以理解为：

```
key
 ↓
hashCode()
 ↓
hash()
 ↓
定位桶
 ↓
发现桶中有节点
 ↓
比较 hash
 ↓
equals()
 ↓
确定是不是同一个 key
```

---

# 16. hashCode 和 equals 的关系

必须牢记：

```
equals() == true
        ↓
hashCode() 必须相同
```

但是：

```
hashCode() 相同
        ↓
equals() 不一定为 true
```

例如：

```
对象 A → hash = 10
对象 B → hash = 10
```

可能：

```
A.equals(B) == false
```

这就是：

> **Hash 冲突**

---

# 17. HashMap 的核心思想

可以用一句话概括：

> **hashCode 用来快速定位桶，equals 用来确认具体的 key。**

完整流程：

```
key
 ↓
hashCode()
 ↓
hash()
 ↓
(n - 1) & hash
 ↓
定位桶
 ↓
hash + equals
 ↓
确定 key
```

这是 HashMap 最重要的思想之一。

---

# 18. 为什么需要红黑树？

如果大量 key 都进入同一个桶：

```
table[5]
   ↓
Node
 ↓
Node
 ↓
Node
 ↓
Node
 ↓
Node
 ↓
Node
 ↓
...
```

链表越来越长。

那么查询：

```
O(n)
```

最坏情况下效率会比较低。

所以 Java 8 引入红黑树。

结构可能变成：

```
table[5]
    ↓
  红黑树
   / \
  /   \
Node  Node
     /   \
   Node  Node
```

理想情况下查询效率可以达到：

```
O(log n)
```

---

# 19. 但是不是超过 8 个节点就一定树化？

**不是。**

后面源码分析需要重点学习：

```
TREEIFY_THRESHOLD
```

以及：

```
MIN_TREEIFY_CAPACITY
```

所以不能简单记成：

> “链表超过 8 就变成红黑树。”

准确理解应该是：

> **当桶中链表长度达到一定条件时，HashMap 会考虑树化，但还需要结合数组容量等条件判断。**

这个我们在下一阶段继续分析。

最终把整个 `put()` 串起来：

```
map.put(key, value)
        ↓
    hash(key)
        ↓
   key.hashCode()
        ↓
   扰动函数
        ↓
    putVal()
        ↓
table 是否初始化？
    ↓
没有 → resize()
    ↓
计算桶下标
    ↓
(n - 1) & hash
    ↓
找到 table[i]
    ↓

│               │

│               │
↓               ↓

                ↓

        ↓                ↓

        ↓                ↓
      覆盖             Hash冲突

                         ↓

```

# 21. 面试版回答

如果面试官问：

> **HashMap 的 put 方法底层流程是什么？**

可以回答：

> HashMap 执行 put 时，首先会对 key 的 hashCode 进行扰动计算得到 hash，然后进入 putVal 方法。第一次 put 时如果数组还没有初始化，会通过 resize 初始化数组。之后通过 `(n - 1) & hash` 计算桶下标。如果对应桶为空，就直接创建 Node 插入；如果桶不为空，则先通过 hash 和 equals 判断是否存在相同的 key，如果存在则更新 value，否则处理 Hash 冲突，将节点插入链表或红黑树。插入完成后还会判断是否达到扩容阈值，如果达到则进行 resize 扩容。


---

我们现在分析：

```
if (p.hash == hash &&
    ((k = p.key) == key ||
     (key != null && key.equals(k))))
```

先不要急着背，我们假设：

```
map.put(key, value);
```

已经通过 hash 计算找到了：

```
table[i]
```

并且：

```
p = table[i]
```

说明：

> **这个桶里面已经有节点了。**

现在 HashMap 要解决一个问题：

> **这个新来的 key，到底是不是桶里面已经存在的 key？**

---

## ① 第一关：`p.hash == hash`

```
p.hash == hash
```

意思：

> 先比较当前节点的 hash 和新 key 的 hash 是否相同。

例如：

```
新 key：
hash = 100

桶中的节点：
hash = 100
```

那么：

```
100 == 100
```

成立。

但是如果：

```
新 key：
hash = 100

桶中的节点：
hash = 200
```

那么：

```
100 == 200
```

不成立。

### 为什么要先比较 hash？

因为：

> **hash 不一样，基本可以直接判断不是同一个 key。**

这样就不用急着调用 `equals()`。

---

# ② 第二关：`(k = p.key) == key`

假设：

```
p.key
```

就是当前节点保存的 key。

然后：

```
(k = p.key) == key
```

实际上包含两个动作：

```
k = p.key
```

先把节点中的 key 赋值给 `k`。

然后：

```
k == key
```

比较两个引用是不是**同一个对象**。

---

## 举个例子

```
String key = "abc";

map.put(key, 100);
map.put(key, 200);
```

第二次 put 的时候：

```
新 key ─────┐
            ↓
          "abc"
            ↑
            │
节点 key ───┘
```

两边引用的是同一个对象。

所以：

```
k == key
```

直接：

```
true
```

那么 HashMap 就可以确定：

> **这个 key 已经存在。**

接下来就不是新增节点，而是：

> **更新 value。**

---

# ③ 为什么不直接 equals？

因为：

```
k == key
```

已经可以判断：

> 两个引用是不是完全指向同一个对象。

如果是同一个对象，那么肯定不需要再调用：

```
equals()
```

所以这是一个**快速判断**。

---

# ④ 第三关：`key != null`

如果前面：

```
p.hash == hash
```

成立，而且：

```
k == key
```

不成立。

接下来：

```
key != null
```

先判断：

> 新 key 是不是 null。

为什么？

因为马上要调用：

```
key.equals(k)
```

如果：

```
key == null
```

那么：

```
key.equals(k)
```

会直接：

```
NullPointerException
```

所以必须先：

```
key != null
```

---

# ⑤ 最后一关：`key.equals(k)`

如果：

```
hash 相同
↓
不是同一个对象
↓
key 不为 null
```

那么最后：

```
key.equals(k)
```

真正判断：

> **两个 key 在逻辑上是不是相等。**

例如：

```
String key1 = new String("abc");
String key2 = new String("abc");
```

这里：

```
key1 == key2
```

是：

```
false
```

但是：

```
key1.equals(key2)
```

是：

```
true
```

所以 HashMap 最终可以判断：

> **虽然不是同一个对象，但它们代表的是同一个 key。**

于是：

> **更新原来的 value。**

---

# ⑥ 现在把整个判断串起来

这段：

```
if (p.hash == hash &&
    ((k = p.key) == key ||
     (key != null && key.equals(k))))
```

可以翻译成人话：

> **先判断 hash 是否相同，如果 hash 相同，再判断是不是同一个对象；如果不是同一个对象，再通过 equals 判断两个 key 是否逻辑相等。**

也就是：

```
新 key
 ↓
hash 相同？
 ↓
是
 ↓
是不是同一个对象？
 ↓
是 → key 已存在
 ↓
否
 ↓
equals 是否相等？
 ↓
是 → key 已存在
```

# ⑦ 那如果不相等呢？

例如：

```
map.put("张三", 18);
map.put("李四", 20);
```

假设：

```
张三 hash = 100
李四 hash = 100
```

那么：

```
p.hash == hash
```

成立。

但是：

```
p.key == key
```

不成立。

然后：

```

```

也不成立。

于是：

> **不是同一个 key。**

但是它们又进入了同一个桶。

这就是：

```

 ↓
下一个节点
 ↓

```

```
 ↓
插入新节点
```

# ⑨ 这里有一个面试高频追问

面试官可能问：

> **为什么 HashMap 判断 key 是否相同，不直接使用 equals，而是先比较 hash？**

你现在应该能够回答：

> 因为 hash 相同才有可能是同一个 key。如果 hash 不同，就可以直接判断两个 key 不相同，不需要调用 equals。先比较 hash 可以减少 equals 的调用次数，提高效率。

# 十二、面试回答：HashMap扩容流程

如果问：

> HashMap什么时候扩容？扩容做了什么？

回答：

> HashMap通过负载因子控制扩容，当元素数量超过 threshold(capacity*loadFactor) 时触发 resize。扩容时会创建一个两倍大小的新数组，并将旧数组中的节点迁移到新数组。Java8 中利用 hash 与旧容量进行判断，元素要么保持原索引位置，要么移动到原索引加旧容量的位置，不需要重新计算 hash，提高了扩容效率。
