# 今天开始考你几个问题（和之前一样）

### 问题1：

为什么对象一般存放在堆中，而不是栈中？

> 对象一般存放在堆中，因为对象的生命周期通常不确定，而栈帧生命周期随着方法结束而销毁。如果对象放在栈中，方法执行结束后对象也会被销毁，无法满足对象长期存活的需求。
---

### 问题2：

为什么堆是线程共享的，而栈是线程私有的？

> 堆存放对象实例，对象可能被多个线程访问，因此设计为线程共享区域。而虚拟机栈保存线程执行的方法、局部变量和调用信息，每个线程执行流程不同，因此必须是线程私有。
---

### 问题3：

JDK8为什么使用元空间替代永久代？

> JDK8使用元空间替代永久代，是因为永久代空间大小固定，加载大量类信息时容易发生内存溢出。元空间使用操作系统本地内存，可以动态扩展，更加灵活。

### 问题1：

为什么 JVM 创建对象时，需要先进行类加载检查，而不是直接分配内存？


>VM创建对象时需要先进行类加载检查，因为创建对象之前必须确认该类已经被加载，并且获取类的元数据信息，例如对象大小、字段信息、方法信息等。如果类没有加载，需要先完成类加载过程，否则无法完成对象创建。

---

### 问题2：

对象创建过程中，为什么要先初始化零值，再执行构造方法？


> 因为 JVM 需要保证对象创建后处于一个确定的状态，避免对象属性出现未初始化的随机数据。内存分配完成后，JVM会先将对象实例变量初始化为对应的默认值，然后再执行构造方法进行真正的业务初始化。

## Q1：

为什么JDK6以后synchronized性能提高？

回答：

> 因为JVM引入了锁优化机制，根据竞争情况将锁分为无锁、偏向锁、轻量级锁和重量级锁，减少不必要的线程阻塞，提高性能。

---

## Q2：

偏向锁解决什么问题？

回答：

> 偏向锁解决单线程重复获取锁的问题，通过在Mark Word中记录线程ID，使同一个线程再次获取锁时无需CAS操作。

---

## Q3：

轻量级锁如何实现？

回答：

> 轻量级锁通过CAS将对象Mark Word替换为线程栈中的Lock Record，如果成功获得锁，失败后进行自旋等待。

---

## Q4：

重量级锁为什么慢？

回答：

> 因为重量级锁依赖ObjectMonitor，线程竞争失败后会进入阻塞状态，需要操作系统进行线程调度，涉及上下文切换。

现在轮到你回答几个问题（和之前一样）🔥

### 问题1：

为什么 synchronized 不直接使用重量级锁，而设计偏向锁和轻量级锁？

> synchronized不直接使用重量级锁，是因为很多场景下锁不存在竞争。如果直接使用重量级锁，会导致线程阻塞和上下文切换，性能较低。因此JVM根据竞争程度设计了偏向锁和轻量级锁，减少无意义的锁竞争。

---

### 问题2：

偏向锁为什么只适合单线程访问？

> 偏向锁只适合单线程访问，因为偏向锁会在对象头Mark Word中记录当前持有锁的线程ID。如果其他线程尝试获取同一个锁，需要撤销偏向状态并升级为轻量级锁，因此多线程竞争场景下偏向锁反而会增加维护成本。

---

### 问题3：

轻量级锁获取失败后，为什么不是立即阻塞，而是先自旋？

> 轻量级锁获取失败后先自旋，是因为锁持有时间通常比较短，如果立即阻塞会产生线程上下文切换成本。通过自旋等待，可以让线程在锁很快释放时直接获取锁，提高性能。如果竞争持续激烈，再升级为重量级锁。

### 问题1：

为什么标记清除算法会产生内存碎片？

>标记清除算法只删除死亡对象，不移动存活对象，因此会导致大量不连续的空闲空间，形成内存碎片。

---

### 问题2：

为什么年轻代适合使用复制算法，而老年代不适合？

> 年轻代对象存活率低，复制少量存活对象成本较低，因此适合复制算法。而老年代对象存活率高，如果使用复制算法需要复制大量对象，效率较低，所以通常使用标记整理算法。

---


### 问题3：

为什么JVM要设计年轻代和老年代，而不是整个堆使用一种GC算法？

> JVM采用分代收集思想，是因为不同生命周期对象的特点不同。年轻代对象存活率低，适合复制算法；老年代对象存活率高，适合标记整理算法。通过针对不同区域采用不同策略，提高垃圾回收效率。

# Day5-7：G1 垃圾收集器

## 一、为什么需要 G1？

我们先回顾之前的垃圾回收器思路。

传统分代：

```
堆
│
├── 年轻代
│   ├── Eden
│   ├── Survivor
│   └── Survivor
│
└── 老年代
```

这种方式有一个问题：

**年轻代和老年代的空间边界比较固定。**

假设：

```
年轻代：4GB
老年代：12GB
```

但某一段时间：

```
年轻代特别忙
老年代比较空
```

年轻代需要更多空间时，不能像一个统一的区域那样灵活选择回收价值高的内存区域。

---

G1 的思路发生了变化：

> 不再把整个堆简单地划分成一块连续的年轻代和一块连续的老年代，而是把整个堆划分成很多大小相等的 Region。

例如：

```
┌────┬────┬────┬────┬────┐
│ R1 │ R2 │ R3 │ R4 │ R5 │
├────┼────┼────┼────┼────┤
│ R6 │ R7 │ R8 │ R9 │ R10│
├────┼────┼────┼────┼────┤
│ R11│ R12│ R13│ R14│ R15│
└────┴────┴────┴────┴────┘
```

每个 Region 可以根据当前情况承担不同角色：

```
Eden Region
Survivor Region
Old Region
```

所以 G1 的名字：

**Garbage First**

核心思想就是：

> 优先回收垃圾最多、回收收益最高的 Region。

---

# 二、为什么 G1 要设计 Region？

这是面试非常喜欢问的。

传统方式：

```
Young
████████████

Old
████████████████████
```

G1：

```
Region Region Region Region
Region Region Region Region
Region Region Region Region
```

这样有什么好处？

假设：

```
Region1：存活90%
Region2：存活10%
Region3：存活20%
Region4：存活80%
```

如果进行垃圾回收：

回收 Region2：

```
垃圾：90%
```

回收收益非常高。

而 Region1：

```
垃圾：10%
```

回收收益低。

所以 G1 可以：

> 优先选择垃圾最多的 Region 进行回收。

这就是 **Garbage First**。

---

# 三、G1是不是完全没有年轻代和老年代？

这里非常容易产生误解。

❌ 不是。

G1 **仍然有年轻代和老年代的概念**。

区别是：

传统收集器：

```
一整块连续的年轻代

+

一整块连续的老年代
```

G1：

```
很多 Region

其中一些Region作为年轻代
一些Region作为老年代
```

而且这些 Region 的数量可以动态调整。

---

# 四、G1最核心的特点：可预测停顿时间

这是面试重点。⭐⭐⭐

例如：

```
-XX:MaxGCPauseMillis=200
```

意思是：

> 希望 GC 停顿时间尽量控制在 200ms 左右。

注意：

⚠️ **不是保证一定不会超过200ms。**

而是：

> G1 会根据目标停顿时间，选择在本次 GC 中回收多少个 Region。

---

例如：

现在有：

```
R1：垃圾90%
R2：垃圾80%
R3：垃圾70%
R4：垃圾20%
```

如果预计：

```
200ms
```

只能回收两个 Region：

那么 G1 优先：

```
R1
R2
```

而不是把所有 Region 一次性处理。

---

所以：

```
传统GC：

我这次要把这一大片区域回收掉


G1：

我这次有一个停顿时间目标
     ↓
能回收多少？
     ↓
选择收益最高的Region
```

这就是 G1 的核心思想。

---

# 五、那么问题来了：

G1怎么知道：

> 一个 Region 中的对象有没有被其他 Region 引用？

这就引出了一个非常重要的东西：

# Remembered Set（RSet）

---

# 六、为什么需要 Remembered Set？

假设：

```
Region A

对象A1
对象A2
```

Region B：

```
对象B1
对象B2
```

现在：

```
B1 ─────→ A1
```

也就是说：

**Region B中的对象引用了Region A中的对象。**

---

现在：

G1准备回收：

```
Region A
```

它需要知道：

> 有没有其他Region中的对象引用A中的对象？

如果每次都把整个堆扫描一遍：

```
Region A
Region B
Region C
Region D
Region E
...
```

成本太高。

---

所以 G1 使用：

## Remembered Set

可以把它简单理解成：

> 记录“其他 Region 指向当前 Region 的引用关系”的辅助数据结构。

例如：

```
Region B
   │
   │ 引用
   ↓
Region A
```

RSet帮助G1知道：

```
谁引用了Region A？
```

这样：

回收 Region A 时：

不用扫描整个堆。

---

# 七、为什么 RSet 很重要？

假设：

```
整个堆：

1000个Region
```

这次只想回收：

```
Region A
```

没有 RSet：

```
扫描1000个Region
```

有 RSet：

```
直接找到：

Region B
Region F
Region X

这些引用了A
```

然后处理这些引用关系。

---

所以：

### 面试回答

> G1通过Remembered Set记录跨Region的引用关系，在回收某个Region时，不需要扫描整个堆，就可以找到其他Region指向该Region的引用，从而降低GC扫描成本。

### 问题1

**G1为什么要把堆划分成很多Region？**


> G1将整个堆划分成多个Region，使年轻代和老年代不再是固定的连续空间，并且可以根据每个Region的垃圾多少灵活选择回收区域，从而提高垃圾回收效率，并更好地控制停顿时间。
---

### 问题2

**G1为什么需要Remembered Set？**

> 堆对象之间存在引用关系，但是gc不知道谁引用了谁，只能从头开始全部扫描一遍，很浪费时间和资源，用remembered set每个region区都会记录谁引用了我，查找很方便

### 问题3

假设：

```
Region A
   ↑
   |
Region B
```

B中的对象引用了A中的对象。

现在G1准备回收Region A。

**如果没有Remembered Set，为什么可能需要扫描整个堆？**

> 如果没有 Remembered Set（RSet），GC 在进行局部垃圾回收（如只回收 Young 区）时，无法单凭 Young 区内部的信息确定哪些 Young 区对象是存活的，必须通过全堆扫描来防止误删对象。

> 避免Remembered Set为了回收一个 Region 而扫描整个堆。

### 问题4 ⭐⭐⭐

**什么是三色标记算法？白色、灰色、黑色分别代表什么？**

|**颜色**|**标记状态**|**含义说明**|
|---|---|---|
|⚪ **白色**|未发现|GC 还没有发现该对象（若标记结束时仍为白色，即为可回收的垃圾对象）。|
|🔘 **灰色**|扫描中|对象已经被 GC 发现，但其引用的其他对象还没有扫描完成。|
|⚫ **黑色**|扫描完成|对象已经被 GC 发现，并且其所有的引用关系都已经扫描完成。|

> 白色=没看过，灰色=看到了但没看完，黑色=看完了。

# 一、为什么三色标记还不够？

刚才我们学的是：

```
白色：没发现
灰色：发现了，但没扫描完
黑色：扫描完成
```

如果GC线程和Java业务线程**同时运行**，问题就来了。

因为：

> GC在标记的同时，业务线程可能修改对象之间的引用关系。

---

# 二、什么叫“漏标”？⭐⭐⭐

看这个例子：

```
A → B
```

GC开始标记。

最开始：

```
A：灰色
B：白色
```

GC扫描A：

```
A：黑色
B：灰色
```

正常情况下：

```
A → B
```

接下来GC应该继续扫描B。

---

但是这个时候，**业务线程修改了引用关系**：

```
A → C
```

原来的：

```
A → B
```

被断开。

如果GC没有正确记录这个变化，就可能出现：

```
A：黑色
B：灰色
C：白色
```

然后GC继续处理。

如果C没有被重新发现：

```
C：白色
```

最终GC可能错误地认为：

> C是垃圾。

但实际上：

```
A → C
```

C明明还活着。

这就是我们说的：

# 漏标

---

# 三、为什么漏标很危险？

因为：

**漏标可能导致存活对象被错误回收。**

所以GC必须保证：

> 并发标记过程中，即使业务线程修改了对象引用关系，也不能把真正存活的对象漏掉。

---

# 四、G1怎么解决？

这里就出现了：

# SATB

全称：

**Snapshot At The Beginning**

你现在不需要死记英文，理解成：

> **在并发标记开始时，对对象引用关系形成一个“逻辑快照”，后续引用关系发生变化时，通过写屏障记录变化。**

核心：

```
并发标记
   ↓
业务线程修改引用
   ↓
写屏障记录变化
   ↓
SATB保证对象不会漏标
```

---

# 五、什么是写屏障？

这个概念你之前学CAS的时候可能没接触过。

简单理解：

> **写屏障就是在程序修改对象引用时，JVM插入的一小段额外处理逻辑。**

例如：

原来：

```
A → B
```

业务代码把它改成：

```
A → C
```

JVM不仅仅执行：

```
A → C
```

还可能通过写屏障：

```
记录引用关系变化
```

让GC知道：

> “这里刚刚发生过引用修改。”

---

# 六、你现在先不要把 SATB 想得太复杂

面试初级/中级阶段，你记住这条链就够了：

```
并发标记
    ↓
业务线程可能修改引用
    ↓
可能产生漏标
    ↓
写屏障
    ↓
SATB记录引用变化
    ↓
避免存活对象被漏标
```

---

# 七、这里有一个非常容易混淆的地方

你可能会问：

> 那为什么不直接把业务线程停下来？

这就是：

# STW

Stop The World。

意思：

```
Java业务线程

线程A ───暂停──────继续
线程B ───暂停──────继续
线程C ───暂停──────继续

GC线程

        ███████
```

所有应用线程暂停。

这样GC就可以在一个相对稳定的对象关系状态下工作。

---

# 八、G1是不是没有STW？

**不是。**

这是非常典型的面试陷阱。

G1仍然存在STW。

只是：

> G1通过Region、并发标记、增量回收等机制，尽量缩短和控制停顿时间。

所以：

```
错误：

G1 = 没有STW ❌


正确：

G1 = 尽量控制STW时间 ✅
```

# 九、G1的GC过程先建立一个整体认识

你现在可以把G1粗略理解成：

```
                G1
                 │
                 ↓
          堆划分成Region
                 │
                 ↓
       年轻代 / 老年代Region
                 │
                 ↓
          并发标记存活对象
                 │
          ┌──────┴──────┐
          ↓             ↓
      三色标记        SATB
          │             │
          └──────┬──────┘
                 ↓
          计算Region回收价值
                 ↓
       优先选择垃圾最多的Region
                 ↓
            Mixed GC
```

# 十、什么是 Mixed GC？

这个是G1非常重要的概念。

以前你学过：

### Minor GC

主要回收：

```
年轻代
```

### Major/Full GC

主要涉及：

```
老年代
```

而G1：

在完成并发标记之后，可以进行：

# Mixed GC

意思：

> **一次GC同时回收年轻代Region和一部分老年代Region。**

例如：

```
Young Region：

Y1 Y2 Y3


Old Region：

O1 O2 O3 O4 O5
```

G1发现：

```
O2：垃圾90%
O4：垃圾80%
O1：垃圾10%
```

这一次如果停顿时间有限：

可能选择：

```
Y1 Y2 Y3

+

O2 O4
```

而不是一次把所有Old Region全部回收。

---

# 十一、这就回到我们之前的问题

为什么叫：

## Garbage First？

因为：

```
Region A：垃圾10%
Region B：垃圾90%
Region C：垃圾80%
```

优先：

```
B
C
```

而不是：

```
A
```

---

# 十二、G1为什么能够控制停顿时间？

这是今天最后一个重要问题。⭐⭐⭐

假设：

```
-XX:MaxGCPauseMillis=200
```

你可以理解成：

> 希望GC停顿目标尽量控制在200ms左右。

G1会根据过去的回收情况估算：

```
回收一个Region ≈ 20ms
```

那么这次：

```
200ms
```

大概可以处理：

```
10个Region
```

于是：

```
选择回收收益最高的10个Region
```

当然，实际G1的预测模型比这个例子复杂得多。

但是面试理解：

**这样理解完全够用。**

# 🔥 Day5最后一轮面试题

今天不要再继续往新知识冲了。

我们来做一次 **Day5总复习**。

你先回答下面4个：

### 问题1

**G1为什么使用Region，而不是像传统分代收集器一样把年轻代、老年代划成固定的连续空间？**

> G1把整个堆划分成多个Region，年轻代和老年代由不同的Region组成，可以根据当前GC情况动态调整各类Region的数量，并且可以选择垃圾较多的Region进行回收。

---

### 问题2

**Remembered Set解决什么问题？**

>  Remembered Set用于记录跨Region的引用关系。当G1回收某个Region时，可以通过RSet快速找到其他Region对当前Region的引用，而不需要扫描整个堆。

---

### 问题3 ⭐⭐⭐

**什么是三色标记？白色、灰色、黑色分别代表什么？**

> 白色：没看见；灰色：看见了但没看完；黑色：看完了。
---

### 问题4 ⭐⭐⭐⭐

假设GC并发标记的时候，Java线程同时修改了对象引用。

**为什么可能产生漏标？G1使用什么机制解决这个问题？**

> 并发标记过程中，GC线程和业务线程同时运行，业务线程可能修改对象之间的引用关系，如果GC没有感知到这种变化，就可能漏掉本来存活的对象。G1通过SATB和写屏障记录引用关系变化，避免漏标。
