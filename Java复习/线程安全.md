## 1. 什么是线程安全？

**线程安全：**  
当多个线程同时访问某个对象、方法或数据时，程序仍然能够保持正确的结果，不会出现数据错乱、状态异常。

简单理解：

> 多个线程同时操作共享资源，结果和单线程执行一样，就是线程安全。

---

## 2. 为什么会出现线程安全问题？

主要原因：

### ① 多线程共享数据

例如：

```
public class Counter {

    private int count = 0;

    public void add(){
        count++;
    }

}
```

两个线程同时执行：

```
counter.add();
```

看似：

```
count++;
```

实际上不是一个原子操作。

底层类似：

```
1. 读取count
2. count + 1
3. 写回count
```

假设：

初始：

```
count = 0
```

线程A：

```
读取 count=0
```

线程B：

```
读取 count=0
```

线程A：

```
+1
写回1
```

线程B：

```
+1
写回1
```

最终：

```
count=1
```

但是实际应该：

```
count=2
```

这就是线程安全问题。

# 3. Java线程安全问题的三个核心原因

面试经常问：

## ① 原子性（Atomicity）

一个操作不可被中断。

例如：

```
count++;
```

不是原子操作。

解决：

- synchronized
- Lock
- AtomicInteger

---

## ② 可见性（Visibility）

一个线程修改变量后，其他线程能够立即看到。

例如：

```
boolean flag = false;


线程A：

flag=true;


线程B：

while(!flag){

}
```

可能出现：

线程B一直读取旧值：

```
flag=false
```

原因：

CPU缓存。

线程：

```
CPU缓存
   |
   |
主内存
```

线程A修改：

```
CPU缓存中的flag=true
```

但是没有及时刷新到主内存。

线程B读取：

```
CPU缓存中的flag=false
```

解决：

### volatile

```
volatile boolean flag;
```

volatile保证：

- 可见性
- 禁止指令重排序

但是：

❌ 不保证原子性

例如：

```
volatile int count;

count++;
```

仍然线程不安全。

---

## ③ 有序性（Ordering）

代码执行顺序可能被 JVM 或 CPU 优化。

例如：

代码：

```
int a=1;
int b=2;
```

可能重排序：

```
int b=2;
int a=1;
```

对于单线程没有影响。

但是多线程可能产生问题。

解决：

- volatile
- synchronized
