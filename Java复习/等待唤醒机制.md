
等待唤醒机制是 **多线程协作的一种通信机制**，主要用于解决：

> 一个线程执行某个任务时，如果发现某个条件不满足，就进入等待状态；  
> 当另一个线程完成某个操作，使条件满足后，再唤醒等待线程继续执行。

核心方法：

|方法|作用|是否释放锁|
|---|---|---|
|`wait()`|让当前线程等待|✅释放锁|
|`notify()`|唤醒一个等待线程|❌不释放锁|
|`notifyAll()`|唤醒所有等待线程|❌不释放锁|

这三个方法属于：

```
Object类
```

因为 Java 中每个对象都有一个监视器（Monitor），线程可以依赖对象锁进行等待和唤醒。

---

# 一、为什么需要等待唤醒机制？

看一个经典问题：

## 生产者-消费者模型

例如：

一个仓库：

```
仓库容量 = 10
```

生产者：

```
生产商品
放入仓库
```

消费者：

```
消费商品
取出仓库商品
```

问题：

如果仓库满了：

```
生产者继续生产
```

会导致：

```
库存超过容量
```

所以：

生产者应该：

```
等待
```

直到消费者取走商品。

如果仓库空了：

```
消费者继续消费
```

会导致：

```
没有商品可消费
```

所以：

消费者应该：

```
等待
```

直到生产者生产商品。

这就是等待唤醒机制解决的问题。

---

# 二、wait()方法

## 作用

让当前线程进入等待状态。

例如：

```
public synchronized void test(){

    wait();

}
```

执行：

```
线程
 |
 |
进入wait()
 |
 |
WAITING状态
```

线程暂停执行。

---

# 三、wait()为什么必须放在synchronized里面？

错误：

```
public void test(){

    wait();

}
```

编译：

```
IllegalMonitorStateException
```

原因：

wait依赖对象监视器。

例如：

```
Object lock = new Object();


synchronized(lock){

    lock.wait();

}
```

流程：

```
线程获取lock锁

        |
        v

执行wait()

        |
        v

释放lock锁

        |
        v

进入等待队列
```

重点：

> wait()会释放锁。

---

# 四、notify()

作用：

唤醒一个正在等待的线程。

例如：

```
synchronized(lock){

    lock.notify();

}
```

流程：

```
WAITING线程

       |
       |
notify()

       |
       v

进入锁竞争状态

       |
       |
重新获得锁

       |
       v

继续执行
```

注意：

notify不会立即执行线程。

例如：

线程A：

```
wait();
```

线程B：

```
notify();
```

结果：

```
线程A被唤醒

但是：

线程B还持有锁

所以线程A继续等待
```

必须：

```
B释放锁

A重新竞争锁
```

---

# 五、notifyAll()

作用：

唤醒所有等待线程。

例如：

等待队列：

```
线程A
线程B
线程C
```

执行：

```
notifyAll();
```

结果：

```
线程A
线程B
线程C

全部进入锁竞争
```

最后：

只有一个线程获得锁。

---

# 六、线程状态变化

完整流程：

```
             start()

NEW ----------------> RUNNABLE


             获取锁

RUNNABLE ------------> BLOCKED


             wait()

RUNNABLE ------------> WAITING


             notify()

WAITING -------------> BLOCKED


             获取锁

BLOCKED -------------> RUNNABLE


             执行完成

RUNNABLE ------------> TERMINATED
```

# 七、经典生产者消费者案例

## 1. 商品类

```
class Box {

    private int count = 0;


    public synchronized void put(){

        if(count == 10){

            try {

                wait();

            } catch(Exception e){}

        }


        count++;

        System.out.println(
            "生产一个，库存:"
            + count
        );


        notify();

    }



    public synchronized void get(){

        if(count == 0){

            try{

                wait();

            }catch(Exception e){}

        }


        count--;

        System.out.println(
            "消费一个，库存:"
            + count
        );


        notify();

    }

}
```

---

## 2.生产者

```
class Producer implements Runnable{


    private Box box;


    public Producer(Box box){

        this.box = box;

    }


    public void run(){

        while(true){

            box.put();

        }

    }

}
```

---

## 3.消费者

```
class Consumer implements Runnable{


    private Box box;


    public Consumer(Box box){

        this.box = box;

    }


    public void run(){

        while(true){

            box.get();

        }

    }

}
```

---

## 4.测试

```
public class Test{


    public static void main(String[] args){

        Box box = new Box();


        new Thread(
            new Producer(box)
        ).start();


        new Thread(
            new Consumer(box)
        ).start();


    }

}
```

运行：

```
生产一个，库存:1
生产一个，库存:2

消费一个，库存:1

生产一个，库存:2
```

# 八、wait和sleep区别（面试重点）

|区别|wait|sleep|
|---|---|---|
|所属类|Object|Thread|
|是否释放锁|✅释放|❌不释放|
|使用场景|线程通信|线程休眠|
|是否需要synchronized|✅需要|❌不需要|
|唤醒方式|notify|时间结束自动醒|

例如：

```
synchronized(lock){

    Thread.sleep(1000);

}
```

结果：

```
锁仍然被占用
```

而：

```
synchronized(lock){

    lock.wait();

}
```

结果：

```
锁释放
```

---

# 九、wait为什么一般用while不用if？

错误：

```
if(count==0){

    wait();

}
```

推荐：

```
while(count==0){

    wait();

}
```

原因：

## 1. 防止虚假唤醒

线程：

```
消费者A

wait()
```

被唤醒：

```
notify()
```

但是：

可能商品已经被其他消费者拿走。

所以：

重新判断：

```
while(count==0)
```

更加安全。

# 十、底层原理（面试）

wait/notify依赖：

```
对象监视器 Monitor
```

每个对象：

```
Object

   |
   |
 Monitor

   |
   |
 EntryList
 WaitSet
```

## 获取锁：

线程进入：

```
EntryList
```

竞争锁。

## wait：

线程：

```
释放锁

进入WaitSet
```

## notify：

线程：

```
WaitSet

移动到EntryList

重新竞争锁
```

流程：

```
          synchronized

               |
               v

          Monitor


EntryList             WaitSet

竞争锁                 等待线程


                     wait()

                        |
                        v


                    notify()


                        |
                        v


                  EntryList
```

# 十一、面试常问问题

## 1. wait为什么释放锁？

因为线程进入等待，需要让其他线程获得锁修改条件。

---

## 2. notify为什么不释放锁？

因为notify只是通知：

> 你可以参与竞争锁了

不是：

> 你马上执行

---

## 3. wait为什么必须在同步代码块？

因为：

wait需要操作对象Monitor。

---

## 4. notify随机唤醒哪个线程？

不确定。

由JVM调度。

---

## 5. notify和notifyAll怎么选择？

一般：

```
notify()
```

效率高。

多个条件：

```
notifyAll()
```

更安全。

---

# 十二、和Lock的区别

`synchronized + wait/notify`

对应：

```
Object.wait()
Object.notify()
```

而：

`Lock`

对应：

```
Condition.await()
Condition.signal()
```

例如：

```
Lock lock=new ReentrantLock();


Condition condition=
    lock.newCondition();


condition.await();


condition.signal();
```

本质：

都是线程通信机制。

---

# 面试总结（一句话）

> 等待唤醒机制是线程间通信的一种方式，通过Object的wait、notify、notifyAll实现。wait使线程进入等待并释放锁，notify唤醒等待线程重新竞争锁，底层依赖Monitor中的WaitSet和EntryList实现，常用于生产者消费者模型。
