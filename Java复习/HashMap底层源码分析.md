# HashMap底层源码分析（JDK8）

## 一、HashMap底层数据结构

HashMap本质：

> 数组 + 链表 + 红黑树

JDK8之后，当链表过长时，会转换为红黑树，提高查询效率。

结构：

    table数组

    0    null
    1    Node
    2    Node -> Node -> Node
    3    null
    4    TreeNode(红黑树)

核心源码：

``` java
transient Node<K,V>[] table;
```

table就是HashMap维护的数组。

------------------------------------------------------------------------

# 二、Node节点源码

HashMap中的键值对会封装成Node对象。

``` java
static class Node<K,V> implements Map.Entry<K,V> {

    final int hash;

    final K key;

    V value;

    Node<K,V> next;


    Node(int hash, K key, V value, Node<K,V> next) {
        this.hash = hash;
        this.key = key;
        this.value = value;
        this.next = next;
    }
}
```

Node结构：

    Node

    hash
     |
    key
     |
    value
     |
    next
     |
    下一个Node

# 三、put方法源码分析

调用：

``` java
map.put("java",100);
```

进入：

``` java
public V put(K key,V value){

    return putVal(hash(key),key,value,false,true);

}
```

------------------------------------------------------------------------

## 1.计算hash值

源码：

``` java
static final int hash(Object key){

    int h;

    return (key==null)?0:
        (h=key.hashCode())^(h>>>16);

}
```

HashMap会让hashCode的高16位参与运算。

目的：

-   减少hash冲突
-   让元素分布更加均匀

------------------------------------------------------------------------

# 四、计算数组下标

源码：

``` java
(n-1)&hash
```

例如：

数组容量：

    16

计算：

    index = hash & (16-1)

得到元素存放的位置。

# 五、第一次put流程

第一次put时：

``` java
if(table==null || table.length==0){

    resize();

}
```

因为table为空，所以创建数组。

默认容量：

    DEFAULT_INITIAL_CAPACITY = 16

创建：

    Node[16]

如果当前位置为空：

``` java
tab[i]=newNode;
```

直接插入。

# 六、hash冲突处理

如果两个key计算出来的数组下标相同：

    table[3]

    Node("Aa",1)

继续插入：

    table[3]

    Node("Aa",1)
           |
           v
    Node("BB",2)

形成链表。

# 七、key相同如何处理

例如：

``` java
map.put("java",100);

map.put("java",200);
```

HashMap判断：

``` java
key.equals(k)
```

如果相同：

覆盖value。

结果：

    java -> 200

------------------------------------------------------------------------

# 八、链表为什么转红黑树

JDK8优化：

当链表长度达到8时，会转换成红黑树。

源码：

``` java
TREEIFY_THRESHOLD = 8;
```

但是还有条件：

``` java
MIN_TREEIFY_CAPACITY = 64;
```

也就是说：

-   链表长度 \>= 8
-   数组容量 \>= 64

才会树化。

否则优先扩容。

------------------------------------------------------------------------

# 九、resize扩容源码分析

HashMap默认扩容：

    16 -> 32

源码：

``` java
newCap = oldCap << 1;
```

也就是：

    容量 * 2

扩容后：

因为数组长度变化，所以元素需要重新计算位置。

------------------------------------------------------------------------

# 十、扩容条件

HashMap默认：

    loadFactor = 0.75

默认容量：

    16

阈值：

    16 * 0.75 = 12

当元素数量超过12：

触发扩容。

# 十二、查询效率

链表：

    O(n)

红黑树：

    O(logn)

所以JDK8引入红黑树优化。

------------------------------------------------------------------------

# 十三、HashMap为什么线程不安全

## 1.多线程put数据覆盖

多个线程同时操作同一个位置：

可能导致数据丢失。

------------------------------------------------------------------------

## 2.JDK7扩容死循环

JDK7扩容使用头插法。

多线程扩容可能形成环形链表：

    A

    ↓

    B

    ↓

    A

导致get死循环。

JDK8改为尾插法解决。

# 十五、HashMap面试总结

## 1.HashMap底层结构？

JDK8：

> 数组 + 链表 + 红黑树

## 2.HashMap为什么线程不安全？

因为：

-   多线程put可能覆盖数据
-   扩容可能产生问题

## 3.为什么容量必须是2的幂？

因为：

``` java
(n-1)&hash
```

效率更高，并且减少hash冲突。

## 4.为什么加载因子是0.75？

经验值：

-   太高：冲突增加
-   太低：空间浪费

## 5.为什么链表超过8转红黑树？

因为：

链表：

    O(n)

红黑树：

    O(logn)

提高查询效率。

## 6.HashMap默认容量

    16

## 7.默认加载因子

    0.75

## 8.树化条件

    链表长度 >= 8

    数组容量 >= 64
