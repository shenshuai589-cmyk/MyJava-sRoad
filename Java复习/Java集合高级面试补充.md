# 一、ArrayList 源码分析

## 1. ArrayList 底层结构

ArrayList 底层：

    Object[] 数组

特点：

-   查询快：O(1)
-   增删慢：需要移动元素

例如：

    数组:

    0   1   2   3
    A   B   C   D


    删除B：

    0   1   2
    A   C   D

    后面的元素需要移动

------------------------------------------------------------------------

# 2. ArrayList 初始化

## JDK8

创建：

``` java
ArrayList list = new ArrayList();
```

不会立即创建数组。

第一次添加元素：

``` java
add()
```

才创建默认容量：

    10

------------------------------------------------------------------------

# 3. ArrayList 扩容机制

默认扩容：

    newCapacity = oldCapacity + oldCapacity >> 1

也就是：

    1.5倍扩容

例如：

    10
    15
    22
    33
    ...

扩容步骤：

1.  创建新的数组
2.  使用 Arrays.copyOf()
3.  复制旧数组元素
4.  替换原数组

------------------------------------------------------------------------

# 4. ArrayList 为什么查询快？

因为：

数组支持随机访问。

例如：

``` java
list.get(5)
```

直接：

    数组地址 + 偏移量

找到元素。

时间复杂度：

    O(1)

------------------------------------------------------------------------

# 5. ArrayList 为什么增删慢？

中间位置插入：

    A B C D

    插入X

    A B X C D

需要移动大量元素。

时间复杂度：

    O(n)

# 二、HashMap 源码分析（重点）

# 1. HashMap 底层结构

JDK8：

    数组 + 链表 + 红黑树

结构：

    table数组

    0
    |
    1 --> Node --> Node

    2

    3 --> TreeNode

------------------------------------------------------------------------

# 2. HashMap 核心属性

默认：

    初始容量：16

    加载因子：0.75

    扩容阈值：

    16 * 0.75 = 12

当元素数量超过12：

扩容。

------------------------------------------------------------------------

# 3. HashMap put流程

执行：

``` java
map.put(key,value)
```

步骤：

## 第一步

计算key的hash：

``` java
hash(key)
```

------------------------------------------------------------------------

## 第二步

计算数组位置：

``` java
index = (n - 1) & hash
```

------------------------------------------------------------------------

## 第三步

判断当前位置：

### 情况1：为空

直接插入。

------------------------------------------------------------------------

### 情况2：存在元素

发生hash冲突。

比较：

``` java
equals()
```

如果key相同：

    覆盖value

如果key不同：

    形成链表

------------------------------------------------------------------------

## 第四步：链表转红黑树

JDK8：

当链表长度：

    >=8

并且数组长度：

    >=64

转换为红黑树。

------------------------------------------------------------------------

# 4. HashMap为什么线程不安全？

多个线程同时修改：

可能导致：

-   数据覆盖
-   扩容死循环（JDK7）
-   数据丢失

解决：

使用：

    ConcurrentHashMap

------------------------------------------------------------------------

# 三、HashSet源码原理

HashSet底层：

    HashMap

例如：

``` java
HashSet<String> set
```

实际上：

``` java
HashMap<E,Object>
```

添加：

``` java
set.add("A")
```

``` java
map.put("A",PRESENT)
```

value 是固定对象。

# 四、fail-fast机制

## 什么是fail-fast？

快速失败机制。

集合遍历过程中：

如果集合结构发生改变：

直接抛异常。

例如：

``` java
for(String s:list){

    list.remove(s);

}
```

异常：

    ConcurrentModificationException

------------------------------------------------------------------------

# 原因

ArrayList：

``` java
modCount
```

记录集合修改次数。

Iterator：

保存：

``` java
expectedModCount
```

遍历时：

比较：

``` java
modCount != expectedModCount
```

如果不同：

抛异常。

------------------------------------------------------------------------

# 五、ConcurrentHashMap

## 1. 为什么需要ConcurrentHashMap？

HashMap：

线程不安全。

Hashtable：

线程安全，但是效率低。

ConcurrentHashMap：

线程安全 + 高性能。

------------------------------------------------------------------------

# 2. JDK8结构

底层：

    数组 + 链表 + 红黑树

保证线程安全：

-   CAS
-   synchronized

------------------------------------------------------------------------

# 3. put流程

大致：

1.  计算hash

2.  定位数组位置

3.  如果为空：

    CAS插入

4.  如果存在：

    synchronized锁住当前桶

相比Hashtable：

锁粒度更小。

------------------------------------------------------------------------

# 六、CopyOnWriteArrayList

## 特点

写时复制。

底层：

    数组

读：

不加锁。

写：

复制新数组。

适合：

    读多写少场景

例如：

-   配置列表
-   黑名单列表

缺点：

-   占用内存
-   写操作慢

------------------------------------------------------------------------

# 八、集合面试高频问题

## 1.ArrayList和LinkedList区别？

ArrayList：

-   数组
-   查询快
-   增删慢

LinkedList：

-   双向链表
-   查询慢
-   增删快

------------------------------------------------------------------------

## 2.HashMap为什么容量是2的倍数？

因为：

``` java
(n-1)&hash
```

计算效率高。

并且可以减少hash冲突。

------------------------------------------------------------------------

## 3.HashMap为什么加载因子是0.75？

原因：

平衡：

-   查询效率
-   空间利用率

太大：

冲突增加。

太小：

浪费空间。

------------------------------------------------------------------------

## 4.HashMap和Hashtable区别？

HashMap：

-   非线程安全
-   允许null key
-   效率高

Hashtable：

-   线程安全
-   不允许null
-   效率低

------------------------------------------------------------------------
