# HashMap源码逐行解析版（JDK8完整版）

> 适用于 Java 后端面试源码学习

------------------------------------------------------------------------

# 一、HashMap整体结构

HashMap底层：

    数组 + 链表 + 红黑树

JDK8之前：

    数组 + 链表

JDK8之后：

当链表长度过长，会转换成红黑树。

------------------------------------------------------------------------

# 二、HashMap核心成员变量

## 1.默认容量

``` java
static final int DEFAULT_INITIAL_CAPACITY = 1 << 4;
```

结果：

    16

HashMap第一次put时创建数组。

------------------------------------------------------------------------

## 2.最大容量

``` java
static final int MAXIMUM_CAPACITY = 1 << 30;
```

最大：

    2^30

------------------------------------------------------------------------

## 3.加载因子

``` java
static final float DEFAULT_LOAD_FACTOR = 0.75f;
```

作用：

决定扩容阈值：

    threshold = capacity * loadFactor

例如：

    16 * 0.75 = 12

超过12扩容。

------------------------------------------------------------------------

## 4.树化阈值

``` java
static final int TREEIFY_THRESHOLD = 8;
```

链表长度达到8可能树化。

------------------------------------------------------------------------

## 5.退化阈值

``` java
static final int UNTREEIFY_THRESHOLD = 6;
```

红黑树节点减少后退化为链表。

------------------------------------------------------------------------

## 6.最小树化容量

``` java
static final int MIN_TREEIFY_CAPACITY = 64;
```

数组容量小于64：

优先扩容。

------------------------------------------------------------------------

# 三、Node节点源码解析

HashMap元素存储在Node中。

``` java
static class Node<K,V>
implements Map.Entry<K,V>{

    final int hash;

    final K key;

    V value;

    Node<K,V> next;

}
```

含义：

  属性    作用
  ------- -------------------
  hash    key计算出的hash值
  key     键
  value   值
  next    下一个节点

为什么key和hash是final？

因为：

HashMap定位依赖key和hash。

修改会破坏结构。

------------------------------------------------------------------------

# 四、hash方法源码解析

源码：

``` java
static final int hash(Object key){

    int h;

    return (key == null) ? 0 :
        (h = key.hashCode()) ^ (h >>> 16);

}
```

核心：

``` java
(h >>> 16)
```

让高16位参与运算。

目的：

降低hash冲突。

------------------------------------------------------------------------

# 六、putVal源码流程

## 1.判断table是否为空

``` java
if(tab == null || tab.length == 0)
```

第一次put：

table为空。

调用：

``` java
resize()
```

创建数组。

------------------------------------------------------------------------

## 2.计算数组位置

源码：

``` java
index = (n-1)&hash
```

例如：

容量：

    16

计算：

    hash & 15

得到数组下标。

------------------------------------------------------------------------

## 3.当前位置为空

源码：

``` java
if(tab[index]==null)
```

直接插入：

``` java
tab[index]=newNode
```

------------------------------------------------------------------------

## 4.hash冲突

如果位置已有元素：

进入链表处理。

结构：

    table[5]

    Node

     |

    Node

     |

    Node

------------------------------------------------------------------------

## 5.key比较

源码：

``` java
p.hash==hash &&
(key.equals(k))
```

如果key相同：

覆盖value。

------------------------------------------------------------------------

## 6.链表插入

如果key不同：

遍历链表：

找到尾部：

``` java
e.next=newNode
```

------------------------------------------------------------------------

## 7.链表树化

条件：

    链表长度>=8

    数组容量>=64

调用：

``` java
treeifyBin()
```

转换红黑树。

------------------------------------------------------------------------

## 8.size增加

源码：

``` java
++size
```

超过阈值：

调用resize。

------------------------------------------------------------------------

# 七、resize源码解析

作用：

-   创建新数组
-   扩容
-   数据迁移

------------------------------------------------------------------------

## 1.计算新容量

源码：

``` java
newCap = oldCap << 1;
```

例如：

    16 -> 32

------------------------------------------------------------------------

## 2.计算新阈值

源码：

``` java
newThr = newCap * loadFactor;
```

例如：

    32*0.75=24

------------------------------------------------------------------------

## 3.创建新数组

``` java
new Node[newCap]
```

------------------------------------------------------------------------

# 八、扩容迁移机制

JDK8优化：

不用重新计算hash。

判断：

``` java
hash & oldCap
```

结果：

## 等于0

位置不变。

## 等于1

移动：

    原位置 + oldCap

例如：

    5

    变成

    21

# 十三、为什么容量必须是2的幂？

因为：

``` java
(n-1)&hash
```

代替：

``` java
hash%length
```

效率更高。

------------------------------------------------------------------------

# 十四、为什么扩容两倍？

源码：

``` java
oldCap<<1
```

原因：

1.  位运算快
2.  保证容量为2的幂
3.  方便元素重新分布

# 十五、JDK7和JDK8区别

         JDK7           JDK8
  ------ -------------- ------------------
  结构   数组+链表      数组+链表+红黑树
  插入   头插法         尾插法
  扩容   重新计算hash   优化迁移
  冲突   链表           链表+树

------------------------------------------------------------------------

# 十六、HashMap线程不安全原因

## 1.put覆盖

多个线程同时put：

可能导致数据丢失。

## 2.JDK7扩容死循环

头插法：

可能形成环形链表。

## 3.fail-fast

依赖：

``` java
modCount
```

结构修改时改变。
