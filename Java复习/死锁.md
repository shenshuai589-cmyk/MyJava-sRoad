
**死锁（Deadlock）**是指多个进程（或线程）在运行过程中，因争夺资源而形成一种相互等待的状态，导致它们都无法继续执行。

### 举个简单例子

假设有两个线程：

- **线程 A** 已经获得了资源 R1，等待资源 R2。
- **线程 B** 已经获得了资源 R2，等待资源 R1。

由于双方都不会释放自己占有的资源，因此：

```
线程A：持有 R1 → 等待 R2
线程B：持有 R2 → 等待 R1
```

两者互相等待，程序无法继续运行，这就是**死锁**。

---

### 死锁产生的四个必要条件（缺一不可）

1. **互斥条件（Mutual Exclusion）**
    
    - 资源一次只能被一个进程占有。
2. **请求与保持条件（Hold and Wait）**
    
    - 进程已经占有至少一个资源，同时又请求新的资源。
3. **不可剥夺条件（No Preemption）**
    
    - 已获得的资源不能被强制夺走，只能由持有者主动释放。
4. **循环等待条件（Circular Wait）**
    
    - 存在一个进程等待环，如：
        
        ```
        P1 等待 P2 的资源
        P2 等待 P3 的资源
        P3 等待 P1 的资源
        ```
        

---

### 如何解决死锁

常见方法有四种：

|方法|思想|
|---|---|
|**预防死锁**|破坏四个必要条件中的一个，例如按固定顺序申请资源。|
|**避免死锁**|在分配资源前判断是否会进入不安全状态，如**银行家算法**。|
|**检测死锁**|允许死锁发生，定期检测是否存在循环等待。|
|**解除死锁**|检测到死锁后，撤销进程、回收资源或回滚到安全状态。|

### Java 中的死锁示例

```
Object lock1 = new Object();
Object lock2 = new Object();

Thread t1 = new Thread(() -> {
    synchronized (lock1) {
        System.out.println("线程1获得lock1");
        synchronized (lock2) {
            System.out.println("线程1获得lock2");
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lock2) {
        System.out.println("线程2获得lock2");
        synchronized (lock1) {
            System.out.println("线程2获得lock1");
        }
    }
});

t1.start();
t2.start();
```

如果：

- 线程1先获得 `lock1`；
- 线程2先获得 `lock2`；

那么线程1等待 `lock2`，线程2等待 `lock1`，程序就会发生死锁。

---

### 如何避免 Java 死锁

- 按固定顺序获取锁（例如总是先锁 `lock1` 再锁 `lock2`）。
- 使用可超时的锁（如 `ReentrantLock.tryLock()`）。
- 减少锁的嵌套和持有时间。
- 尽量使用无锁或并发安全的数据结构。

**一句话总结：**

> **死锁就是多个进程（或线程）互相等待对方释放资源，导致所有相关进程都无法继续执行的现象。**
